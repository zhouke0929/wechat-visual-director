# 主题创作流程

目标：把用户的参考或风格描述，发展成**有联想、有构图、有细节的完整主题**，不止给通用卡片换色。推荐用户提供喜欢的组件截图，更容易对齐审美；仅有描述也支持探索，不承诺两种输入具有同等的视觉稳定性。下面是唯一的创作主线；字段查 `theme-packs.md`，设计完成后读 `theme-visual-checks.md` 做交付检查。

## 1. 看懂参考，同时展开联想与搜索

先实际看图，找出值得保留的具体关系：文字怎样成为焦点、相片与纸边的比例、标签或装饰怎样连接。色板和物件名称只是起点。仅有描述时，提炼用途、气质与约束，再寻找可实际查看的成品排版或组件，把抽象方向落成具体视觉参考；不要求用户先准备图，也不把描述直接套进通用卡片。明确缺失的指定图片请其补充，不假装看过。

信息足够就继续全套；只有重要方向冲突、可行解释差异很大时，才用简短方向说明或少量试样请用户确认，不给每次创作新增审批关卡。用户禁用联网或找不到可用参考时如实说明，基于描述探索，不伪称已有参考支持。

**搜索是正常创作步骤，不是灵感耗尽后的补救。** 用户允许联网时，即使已有一个组件，也沿下面两条线寻找可实际查看的相关组件；可查秀米、135 编辑器或其他公开设计来源，不要求来自指定网站：

- **解决布局问题的组件参考**：先选原参考对应位置和正文里容易退化成通用卡片的关键关系，再搜能够承载它们的实际排版，例如提问与解释怎样连接、两个观点怎样并置、词条与定义怎样归属。不要只搜主题名称；看到一个好片头后，也不能停止正文参考搜集。来源不必同主题，借鉴组织关系而非外观。
- **联想到的元素参考**：从场景、相邻物件、材质与活动发散，再搜索这些元素如何作为贴纸、边角、标签、分隔或画面框架使用。

先从场景、相邻物件、材质与活动展开，再按用途与气质筛选；不要把第一个符号或容器定成全套答案。联想用来拓宽选择，不是要求所有主题都加物件或装饰。

实际打开图片看构图；搜索摘要不算看过。区分**物件参考**与**内容组件参考**：前者提供联想，后者应展示实际内容与设计共同成立的完成态。只提供题材或排版方法的资料可辅助，但不能代替当前布局问题的视觉依据。挑选时看它补上什么可见收益，用一句话记“借鉴什么、用在哪里”，不因主题名称相关就采用。必要时跨主题搜组织关系，不逐角色找来源或凑数量；不复制会员素材、代码、原作文字或标志。

参考是否够用看它能否帮助作出当前设计选择，而不是看搜索次数。只找到节目单、海报或整页氛围时，仍需补正文较弱位置；不能把“看过一个相关页面”当作选材完成。关键联想来源无法查看时，先检查是否尚未加载，再围绕缺口换可见的公开来源，不把失败链接当作已采用参考。若最终只剩原图的单一符号，检查互补的承载或细节是否不足，而不直接将它缩放后分发全套。找到足以支持选择的参考即可，不无限搜、不逐角色强配来源；访问受限如实说明，不绕过登录/付费。保留简短选材笔记，不写长篇报告。


## 2. 选择能共同成立的视觉家族

先为关键正文选择**内容承载方式**，再选择点缀。用短笔记回答：**阅读关系 → 承载结构 → 文字落点与细饰连接**。例如同样是纸面，可以用主副联连接问题与解释、页签归属词条、相片与旁注建立对应、开放摘句突出停顿；这是可选的思考方式，不是固定模板，也不是所有主题都做纸面。先想内容放在哪、从哪读到哪，再画轮廓。只写“问答分层、A/B比较、加卷轴”还没有作出构图选择。

关键构图尚不明确时，在现有试样中选正文重点，用**相同短文、长文和手机尺度**比较少量有实质区别的方案。先排除窄列、遮挡等阅读问题，再比较标题体量、长正文重心、字体与空间、轮廓和细饰形成的完整画面。淘汰一个挤字方案，不等于另一个已具表现力；同框只换标签、配色或图标也不是构图选择。候选都弱时补互补参考，替换弱候选，不扩成两套完整主题或用户审批。已有明确、成立的设计或局部修改不强制重选。

同时考虑三件事：

- **内容承载与轮廓**：不要先画一个统一矩形，再给各角色更换标签。借鉴参考中的裁切、折叠、贴附、开口、错位、连接或字体空间，让它改变文字的入口、归属与阅读顺序；挑符合当前主题和内容的方式即可，不全用。矩形可以保留，关键是正文重点不只靠换底色、边线、齿孔和图标区分。
- **关联物件和细饰**：物件可以连接文字与边缘、扣住纸片、形成入口或收尾，也可以只是适量点缀；不要每个角色右上角放一个独立小图标。保留一致线宽、曲率、填色与细节尺度，不把联想全部降成直线，也不让装饰挤压正文。
- **阅读节奏**：片头、章节、问答、比较和图文位承担不同任务；给重点设计表现力，给正文、导语、普通列表留出安静空间。表达手段由参考与用户约束决定，也可用字体、比例和空间扩展，不硬加物件。

画面表现也值得设计，不要求每个小装饰都承担信息结构。与主题一致的贴纸、线描、局部填色、材质感或边角细节，可以只提供气氛与精致感；同时看轮廓、文字比例与细饰怎样形成整体。不要因“正文优先”把所有角色降成无装饰色块，也不要把“有设计感”机械等同于异形或结构复杂。它们是否好看、是否打扰阅读，要在真实手机画面判断。

统一靠画风，变化靠内容组织；不是“装饰越少越安全”，也不是每个组件都必须不同。选择值得保留的招牌造型，让它在合适的位置充分表现，其它结构与它形成主次和互补。相同功能可复用同一结构，不同功能也可共享细饰；警惕的是整套承载结构无差别套用，不是同一物件再次出现。普通角色可简洁，不设色块占比、异形数量或图标数量配额，也不把非矩形当作创作目标。

## 3. 先做有代表性的设计，再自动扩展全套

用真实受控渲染做内部试样：先做原参考对应的角色，再覆盖高频章节、不同关系的正文重点，以及**图文位**。数量由方向决定，不设“六个组件”关卡。用户给了照片边框参考，就将其比例、边界或贴附关系用于 `image_caption` 的设计，并装入真实测试图片查看；不能只提取相框配色或用空白占位块声称已完成。

编写时按 `theme-packs.md` 查询声明式节点和字段。`drawing` 可原创绘制物件、贴纸、边带，核心编译为透明 PNG；文字与真实 `media` 仍独立可编辑。图片框表达的是框与照片的关系，不把照片和正文截图化。已知安全与字段边界在制作时遵守；少量原型可先运行 `theme validate` 暴露不支持的能力，但不要让警告清零取代设计。

实际查看原型与参考；完整 `theme review` 后运行截图脚本并打开生成的 `component-overview-*.png` 同尺度总览（命令见交付检查）。原型阶段可先并排查看现有试样，不必提前跑全部用例：
- 关键的轮廓、贴附或相框关系是否真的看得见？
- 参考与联想是否成为可见的设计选择？对照原参考的比例与连接，看标题、长正文、空间和细节是否共同形成重点，而不只是角色各有标签、边线或图标。不要求所有角色都复杂或不同。
- 手机尺度的标题、编号和正文是否依然优先，细饰是否清楚而不粗糙？

若只是同一容器换色或贴不同图标，回到该角色的布局问题找互补参考，改组织关系，不再往原方框上堆装饰。设计成立后自动扩展全部 21 个角色，不等用户逐个提改法。保持家族感，不为求不同混入无关风格；表格和行内强调同步协调。普通角色可以简洁，但不能用原样模板冒充已设计。

**全套覆盖也包含风格覆盖。** 除片头、引用、相框这些容易体现特色的位置，还要检查问答、案例、比较、概念、提示和总结等实际重点。它们可以共享结构或保持克制，但不能默认把弱角色留给“通用卡片 + 本次配色”，再用几个强组件替整套通过。提醒类组件可保留清楚的警示层级，概念类可保留简单的定义结构；怎样用同一家族的字形、比例、标签边界或适量细饰融入主题，由当前参考决定，不套固定图案答案。普通角色不必争夺视觉焦点。

布局字段写齐、未命中原样模板提示，都不证明已设计：换标签、调边距或加感叹号也能避开精确模板比较。实际看普通外观是否确实适合该参考与角色。

细饰优先占用已规划的页角、标题侧边或边界间隙，重新分配留白，而不是在旧内边距上再加一整行图案。形态表达不了时说明具体限制并给出替代设计；不先把所有创意降成色块和线条，也不放宽安全边界。

## 4. 完成后，评审实际画面并闭环修订

执行 [主题交付检查](theme-visual-checks.md)。程序负责字段、覆盖、资产和部分布局风险；Agent 仍须实际看图判断“有没有设计感”和“读起来是否舒服”，用户决定最终偏好。

**先看画面，后看解释。** 宿主支持且当前任务允许委派时，发起一次只读的独立视觉评审；不要新建用户可见对话或自动扩大为多 Agent 流水线。不支持或不允许时，由当前 Agent 按同一约定换评审视角自审，明确记录为自审；没有看图能力则只报告实际完成的程序检查。用户明确要求不增加评审调用时尊重该限制。

首次给评审者的输入仅包含：用户原始需求与约束、可读取的原参考及采用的公开组件参考、原稿、当前版本的原尺寸组件总览与长短试样、正常文章和版本标识。不提供生成者的设计说明、自评分、旧主题、修订史或预设缺陷清单；需要查证可读当前主题源文件，不把说明当作效果证据。修订复核再提供原反馈与受影响画面的前后版本。评审者只读，不改文件、调用微信、付费服务或联系其他对话。

**同一次评审给出阅读与构图两个判断，不增加一轮。** 阅读看层级、空间、换行和图像完整。构图先横看正文重点，再纵看长试样和正常文章，分别核对：

- **需求符合**：是否遵守用户用途、气质与禁用项，是否转译了参考中值得保留的视觉关系？符合约束或主题名称，不等于画面表现已经达标。
- **正文表现**：先判断文字入口、归属与连接是否清楚，再看字体、比例、空间、轮廓与细节怎样形成重点、层次和精致感。依据当前风格实际使用的视觉手段判断，不以是否有图案、颜色或异形作为通过条件。指出具体画面效果，不以功能说明或造型名称作证。
- **成篇取舍**：哪些招牌造型、强构图值得保留，哪些位置因使用频率、尺度或整套结构套用而趋同？先分清特色本身与使用方式，再调整角色分工和轻重。合理复用不必改，安静角色服务阅读；某个漂亮引用或相框也不能替其它关键正文位置通过。

**满足约束、功能清楚、视觉表现是不同判断，不能互相代替。** 构图结论依据正文表现、成篇取舍与用户目标；说明强位置的可见效果，以及最值得改善的位置与原因。阅读可用但关键表现不足时，保留“可读、构图待修”，不降为可选润色或用户偏好。无具体不足允许通过，不为证明评审有效凑反馈；不设物件、异形或装饰配额。补充尺寸问题注明范围。

自审与独立评审使用同一标准。自审先放下自己的设计说明，横看不同正文角色，主动检查最弱位置，再纵看长文和正常文章；不要只举最好的片头或相框作证。用“功能清楚”“符合风格”等解释代替画面证据时，回看对应位置，而不是直接放行。

重点反馈按实际影响排序：阅读阻断优先；阅读可用后，关键构图不足优先于零散细节修整。图文边框用真实图片核对，原稿未用角色由试样补看，不改原稿凑覆盖。参考冲突或偏好意见回到用户约束判断，不无条件执行。

默认一次完整评审、一轮重点修订、原评审者只读复核受影响范围；不能委派时自审。先保留成立的强构图与家族特征，再修弱位置：重复不等于造型失败，先调整它的使用方式，必要时补互补参考、改变承载关系。阅读修复不自动关闭设计反馈，也不以全局删色块、去矩形或换细线纸页代替改善。保持文案、图片和宽度相同，核对关系改善、特色保留与阅读回退。参数试验先局部截图，选定后复核，定版做一次全量回归；共用能力变化扩大范围。无具体问题不强制修订，方向不成立才重选；不无限重试或增加评审调用。未解决的问题如实记录。

排字微调也须保住已成立的构图和层级，不以缩小全套标题或降到正文字级作为孤字修复。长标题的主尺寸、补充适配判断与承载修法见 [交付检查](theme-visual-checks.md#长标题先判断影响再修承载)；提示减少不是视觉改善的替代证据。

保留一份简短评审回执：版本、实际看过的范围、独立评审/自审/未目视、阅读与构图两个判断及综合结论、重点反馈、采纳或不采纳理由、修前修后证据与未测项。构图修订用一句话指出原先缺失的关系和修后可见变化；没有实际看过则保留未验证，不靠设计说明宣告改善。无需逐角色长篇论证或额外评分表，也不把评审文书当作用户必须理解的交付物。其他 Agent 或用户检查本轮结果，不能自动证明未来所有主题都达标。

交给用户的是**完整文章入口 + 全组件入口 + 一句设计说明 + 必要待测项**。让用户看产品效果，不让其理解内部评测文件和过程。
