# 风格转译与视觉验收

用于从参考图或风格描述创建独立新主题。节点、字段、安全和交付契约仍以 `theme-packs.md` 为准。本流程是 Agent 的内部创作步骤，不新增用户确认关卡，不强制每轮都向用户展示草图或表格。

## 1. 先定义看得见的设计目标

实际查看参考，挑出最能决定其辨识度的少数视觉关系，通常 2–3 项足够。不要只写物件名、风格名或“高级、精致”。区分：

- **观察**：外轮廓怎样转折，线条怎样弯曲/交叠，图形和文字如何占据空间，细节在哪里集中、哪里留白。
- **迁移**：哪些关系进入标题、章节或内容组件；哪些只适合小装饰；哪些因白底、长文或用户禁忌需要改变。
- **不迁移**：原作文字、商标、具体人物与事件、整页高密度背景等。简化不等于把全部特征抽掉；保留关键轮廓或空间关系，减少次要重复细节。

用简短设计记录将“参考特征 → 目标角色/位置 → 实际截图 → 观察到的差异”连接起来。它是主题包之外的工作文件，不向 `theme.json` 增加未知字段。没有参考图时，从用户描述推导可见目标，并标为设计假设，不声称来自图片观察。

**判别问题：去掉主题名称和风格说明，只看轮廓、构图和字号层级，还能辨认这个方向吗？** 只剩颜色和一个小图标，不足以支撑“全新风格”；但极简参考也不应被强行加花纹。

## 2. 用内部原型验证目标，不先铺满清单

从最能检验上述视觉关系的角色开始。通常包括片头、会反复出现的章节标题，以及一个正文重点组件；单组件参考先做其对应角色，再加入不同信息关系。数量由设计决定，不把“六组件”变成固定门槛。

只用真实受控布局渲染原型，不拿另写的展示 HTML、示意图或无法安装的设计稿充当效果。先执行 `theme validate` 处理阻断，再以可安装样本或核心预览截图与参考对照。此时允许局部覆盖，但不交付为完整主题。

重点核对：

- **轮廓与比例**：承诺保留的形态实际存在吗？一个复杂轮廓被替换成普通矩形时，不能仅凭相近色板判为符合。
- **文字与装饰的关系**：装饰是在组织边界、分组或阅读方向，还是只在普通卡片上方贴了个图标？标题仍是首要焦点，不附加与原文无关的主题口号。
- **细节尺度**：按正常手机显示尺寸看线条、间隔和小图案；放大才看得清、缩小成杂线或空白的细节需要重新设计。不要通过把文章字号整体缩小来容纳装饰。

`drawing` 不必退化成两点直线：可在契约预算内使用多点折线近似弧线，并配合椭圆和受控布局；先观察实际曲率和边缘质量。它仍不是任意矢量插画工具，不能擅自添加不支持的曲线路径、资源或代码。角色的 `layouts` 优先于基础构图预设，令牌名称不证明对应形态已渲染。

## 3. 自查后修订，再扩展家族

把原型截图和参考放在可比较的尺寸查看。全页缩略图用于看节奏，局部原尺寸截图用于看线条、比例和文字；一张缩成细长条的全页截图不能支持细节验收。

对每个核心目标记录“已体现 / 有差异需修订 / 当前能力无法表达”，并指向实际截图位置与可见理由；这是视觉判断，不是自动打分。发现差异时优先修改最影响辨识度的形态或空间关系，保留修前和修后证据。不要只修 Schema 警告、改名字或删标签，就声称完成了视觉打磨；也不为凑迭代次数制造修改。

若同一目标经过有针对性的修订仍无法表达，说明具体能力缺口以及已经尝试的方式。不要无限加节点、放宽安全约束或把丢失关键特征的结果报为达标；提供明确标注的可用近似或未完成原型，只有需要用户改变方向/范围时才请求选择。

原型成立后，自动扩展全套角色。由参考的物件、场景或形式联想出相互关联、轮廓不同的元素，再用统一的线宽、色板与细节尺度组织：边界、编号、转场、重点区域可以承担不同任务。不要给所有角色贴同一图标，也不要把“每个组件都不同”理解成互不相关的花样。普通段落、导语、列表与图注可以克制。

扩展前在设计记录中列出简短的**关联候选与取舍**：从原物件的结构、制作工艺、相邻物件或场景各自寻找可能的形态，而不只是对主图标旋转、缩放或换色。例如参考邮票时，可以发展邮戳、信纸折角、路线与信封开合的关系；这些是联想方式的例子，不是所有主题的固定元素菜单。仅选择能服务本次参考和阅读功能的家族，说明哪些用于边界、哪些用于序列、哪些用于重点，哪些舍弃。灵感不足且允许联网时寻找相关参考并记录来源，不把搜索到的另一种风格直接混入主题。

将**主题母题**与**重复图标**分开：曲线走势、边角处理、双线间距、印刷或装订节奏也能让组件属于同一家族。检查高频角色连排时，如果只是同一个图案出现在不同盒子上，应调整结构或减少重复；不以装饰数量证明风格丰富度。最终成篇图应同时有重点和安静区。

### 细饰与空间复核

结构成立后再看细节完成度：问答、对比、总结等容器即使易读，也可能只剩通用圆角、色块和分隔线。参考确有装饰性、且用户希望更精致时，从已选关联家族中发展少量适合这些位置的细饰；它们可以增强辨识度，但不能替代轮廓、信息层级与构图设计。极简参考或用户禁止图案时，用边角、线条收口、对齐与疏密打磨，不强行加画。

- **按位置选择，而非分发图标。** 判断细饰是陪衬标题、收住页角、连接边界还是提示转场，再选择适合的轮廓与方向。同一参考可以产生相关但不同的小形态，也可以在合适位置重复；不要给每个角色配图，也不要把某次成功的羽笔、书扣、卷草等固化成新主题菜单。允许联想，但不凭空给正文增加物件事实或栏目名称。
- **先分配空间，再增加图案。** 优先使用已有标题侧栏、页角或边界间隙。加入图案时重新核算原有内边距、图案高度和外边距，避免在旧留白上再叠加一行；仍须为正文保留安全间隔。适合边线的图案用 `ornament_rule`；不适合时保留合理独立空间或改位置，不压扁图形，也不用重叠遮挡正文来伪造紧凑。
- **精修形态，不靠缩小掩盖粗糙。** 检查弧线是否生硬折断、线条端点与连接是否干净、线宽是否一致、透明画布是否含过多无效空白。按正常手机尺寸确认形态仍可辨；放大图只用于定位问题，不作为最终观感依据。受控 `drawing` 能表达时使用核心 PNG 编译，表达不了时如实说明，不放宽包的安全边界。
- **比较修改前后，而非只数装饰。** 保持相同文案和宽度，对照局部截图与文章上下文：细饰是否增加了与参考相关的精致感，是否抢过标题或编号，是否让组件明显变高、正文变窄或转场变碎？变差时调整或撤回，不因已画好而保留。总览中安静的正文、列表和已足够鲜明的组件不必一起加饰。

这些是条件性设计判断，不是每个主题必须具备的图案数量、固定像素尺寸或额外用户审批步骤。设计记录只需保留关键取舍和对应截图，复用的是判断方式，不是本次造型。

## 4. 检查风格有没有延续到真实文章

21 个布局齐全后，使用正常组件密度的文章复核首屏、正文中段和收尾，并检查 320/390/600px 的长短文案。不要为了展示设计向正文补造事实或塞满全部组件。

- 遮住片头再看中段：高频标题和重点组件是否仍可见同一设计语言？如果风格只存在于片头的小装饰里，应重新设计高频角色，而不是给每段加图案。
- 查看至少两种不同信息关系：列表、对比、案例等是否各自清楚，而非相同盒子换颜色？沿用通用结构本身不违规，问题在于核心角色是否形成了所承诺的独立外观。
- 检查长文阅读：编号是否占宽过多、细线是否重复得像表格、留白是否打断关联内容、连续组件是否太密或过于空泛；零横向溢出不能证明这些都合格。
- 标题的文字和章节编号负责定位，装饰不应夺走主焦点；在手机实际尺寸检查视觉重量，不把“图案尺寸必须小于数字”写成僵硬规则。高频标题尤其要克制，片头可以承担较强的主题表达。
- 普通分点的标记与正文首行应同行，换行后对齐正文起点。优先用 `marker_row`，不要在 `repeat` 中把标记和块级 `field` 当成两个纵向孩子；确有分步卡片语义时才刻意上下分层。
- 装饰属于边界时使用 `ornament_rule`，让图案与两侧线在同一条低矮装饰带中，而不是在线下再增加一整排图标。正文仍在正常流中，不能靠绝对定位、强制零高度或负边距把它压上去；检查长标题和多行正文是否安全。较高的叙事插图确有意义时可保留独立空间，不将所有图案强行压扁。
- 换入不同对象文案，确认固定标签没有给正文擅自命名。实际采用图片的文章还要检查图文比例；纯文字文章可用于视觉检查，但不证明图片交付通过。
- 对新增细饰比较长短文案下的位置、文字可用宽度、组件总高度及前后间距；检查 PNG 完整加载、缩放比例、与正文是否相交。自动几何检查只能排除部分故障，仍需看正常手机尺寸下的清晰度和整篇节奏；将新增图案及布局纳入后续微信保存后复核，不沿用旧版本的通过结论。

## 5. 用证据交接，不以技术结论替代审美

设计记录保持简短，包含：核心目标与截图对应、关键修订前后差异、完整主题与正常文章截图、尚存限制。用户回执只给有用的预览链接、简短风格说明和必要的待测项，不要求用户读内部过程。

分别报告布局覆盖、视觉自检和微信保存后实测。视觉自检允许存在判断误差；不要输出无依据的满分、还原百分比，或用 `findings=0` 声称美观通过。最终风格是否符合用户预期，仍由用户决定。
