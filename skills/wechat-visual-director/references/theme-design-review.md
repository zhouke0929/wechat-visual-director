# 主题创作流程

把一个参考组件、整张图片或风格描述，发展成有联想、有正文构图、有细节的完整主题。主线只有：**看参考并找关联 → 定正文承载关系 → 扩展全篇 → 校验与看图修订**。不是通用卡片换色，也不是把同一图标发给所有组件。

## 1. 看参考，搜索组件，展开联想

实际查看参考，抓住可见关系：文字落点、主副比例、相片边界、标签贴附、装饰怎样连接边缘。色板和物件名称只是起点。指定图片缺失就请用户补充，不能假装看过；无图可从描述提出方向。

允许联网时，搜索是正常创作步骤。沿两条线找可实际查看的参考（秀米、135 或其它公开设计来源均可）：

- **内容组件**：围绕当前阅读任务找文字怎样组织，如问题与解释、两种观点、词条与定义、照片与旁注。好片头不能代替正文参考；必要时跨主题借组织关系。
- **关联元素**：从场景、相邻物件、材质与活动发散，再看它们怎样成为贴纸、边角、标签、分隔或框架。海边可以联想到椰树、泳圈、贝壳、旅行照片与相册角贴，但这是示例，不是新主题固定菜单。

先展开再筛选。实际打开图片，搜索摘要不算看过；区分物件参考和内容组件参考。每个采用的参考只记一句“可见关系 → 适用阅读任务”与真实来源，不逐角色凑来源数量。不绕过登录/付费限制，不复制会员素材、原作文字、代码或标志；搜索受限如实说明。

## 2. 先让正文构图成立，再选轮廓与点缀

先决定关键正文的**阅读关系 → 承载结构 → 文字落点与细饰连接**，而非先画统一矩形再换标签。短标题怎样引入长解释、两个观点怎样对应、词条怎样归属定义，需要在画面里成立；“加票券/做问答”只是名称，不是构图选择。

在内部试样中，用相同短文、长文和手机尺度比较少量关键正文方案。正文组织不变、只换标题条或图标是装饰变体；优先选长正文也成立的方案。候选都退回通用卡片时补互补组件参考，不生成两套完整主题或增加用户审批。极简、局部修改、已认可设计不强制重选。

统一靠画风，变化靠任务分工和强弱。借参考的裁切、折叠、贴附、开口、错位或字体空间，改变内容入口、归属与连接；按需选用，不全用。关联物件既可参与结构，也可适量点缀，保持线宽、曲率、填色和尺度一致，不把所有联想降成直线或统一右上角图标。

保留成立的招牌造型，调整它在哪些角色出现、频率和尺度，不因重复就删掉特色。矩形、同功能复用、安静角色都可以成立；不设色块比例、异形或装饰数量配额，不以去矩形为目标。普通正文默认白底；极简或禁图案需求用字体、比例与空间表达。

## 3. 真实试样成立后，自动扩展全套

编写时读 [主题包契约](theme-packs.md)，用声明式 layouts 与受控 drawing 原创设计，base_theme 只作语义和兼容兜底，不拼官方外观，不写任意 HTML/CSS。模板是字段骨架，不是成品外观；表达能力不够时说明具体限制和近似方案，不绕过安全边界。

内部试样先覆盖参考对应角色、高频章节、不同正文关系和图文位，数量由方向决定，不设“六组件”关卡。照片边框参考须用真实测试图片核对框、照片与图注，不能只用占位块或提取配色。drawing 编译为透明 PNG，文字与 media 保持独立可编辑，不把正文或照片截图化。

实际看参考与渲染后，自动扩展全部 21 个布局角色，同步协调表格与行内强调。基础导读、引用、列表可以安静，但不能原样模板回退冒充设计；原稿没用到的角色在独立试样里检查，不往正常文章塞组件或图片凑覆盖。细饰利用页角、标题侧边和边界间隙，重新分配留白，不在旧内边距上叠一整行大图案。

默认完成整套；明确局部范围、重要方向冲突或真实能力阻断才暂停。缺少微信凭据不阻断本地设计。

## 4. 校验、看实际画面，集中修订后交付

完成后读 [主题交付检查](theme-visual-checks.md)。程序判断字段、覆盖、资产与布局风险；实际画面判断阅读和构图。先横看关键正文总览，再纵看长文与正常文章首中尾，不能只看漂亮片头或零溢出。

同一次评审分别回答：

- **阅读**：标题与编号是否优先，列表标记是否同行，长正文是否有可用宽度，图片/线条是否完整，间距是否正常。
- **构图**：风格辨识（颜色、物件、画风）和正文表现分开。用画面中的文字落点、主副比例与连接作证；角色名称、边框不同或加了图标不能替关键正文通过。指出一个值得保留的强关系，以及最值得改善的位置和缺失关系；没有具体不足允许通过。安静和极简角色可由字体、比例与空间成立。
- **成篇取舍**：分清特色细饰共享与整套结构套用。先保留强构图，再调整弱角色分工、频率、尺度或承载关系；不全局删色块、去矩形、改成同一种细线纸页。

支持且当前允许委派时做一次只读独立视觉评审；否则按同一标准自审并标明。评审输入仅含原始需求/约束、实际参考、原稿、当前版本的原尺寸总览/长短试样/正常文章及版本标识；不给作者解释、自评分、旧主题、修订史或预设缺陷。评审者只读，不改文件、联系其它对话或调用外部服务；需要时可查当前主题源文件。没有看图能力则仅报告实际程序检查。

默认一轮重点修订，阅读阻断优先，其后处理影响明确目标的正文构图。阅读修好不自动关闭设计反馈。保持文案、图片、宽度一致，参数试验先局部截图；选定后复核受影响范围，定版一次全量回归，共享变化扩大检查。不增加评审轮数或无限整套重做，意见冲突按用户约束判断，未解决问题如实保留。

简短回执记录版本、看过的范围、评审方式、阅读/构图判断、采纳理由、修前修后证据与未测项。没有看图不凭设计说明宣告改善；知情代修不冒充新会话迁移通过。交给用户的是**正常文章入口 + 全组件入口 + 一句设计方向 + 必要待测项**，不是内部评测文书。微信真实操作仍需授权，本地通过不代表保存后兼容或用户偏好已确认。
