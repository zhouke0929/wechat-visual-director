# 主题交付检查

在完成设计后读取；这是兜底清单，不是创意菜单。字段、命令、报告解释与微信风险见 [主题扩展包契约](theme-packs.md)。制作原型时也可提前查具体风险，不需要先读完全部检查再想设计。

## 1. 程序检查

- 执行 `theme validate`，处理结构与 `rehearsal` 阻断；完整主题的 `coverage` 应覆盖全部 21 个角色。`partial` 继续补齐，不把模板占位当作设计完成。
- 执行 `theme review`，提供可安全使用的真实测试图片；以工作台手机视口 405px（正文净宽 357px）和校对视口 648px（正文净宽 600px）为主验收，正文净宽 320/390px 为补充适配。工具同步工作台的左右留白、字体调整和换行规则，不把正文净宽当作手机视口。支持环境中运行随 Skill 分发的截图脚本，检查字段、溢出、图片加载、长文净宽与标题侧栏提示；传入 `--article` 同步检查正式渲染的正常文章。命令和参数见契约的“换文章复核”。旧核心或工具不可用时完成可做的等价检查，明确缺口，不伪报执行。
- 核对正文、列表项、图像绑定和组件语义完整，不为触发样式改事实。固定标签不能给新文章擅自命名对象、地点或来源；比较、案例、证据换一组不同对象的文案复核。
- 保存主题与渲染版本、报告和修订证据。新检查目录不覆盖旧失败结果；报告与实际交付版本应一致。带 `--article` 的截图工具同时产出 `article-preview.html` 和各档位 HTML，交付入口优先链接这些实际检查的页面；自行写导航时要切换对应文档，不能只改变 iframe 宽度而遗漏字体缩放与预览规则。

局部修订可在新的 `theme review` 材料上运行截图脚本 `--roles <受影响角色...>`，仍覆盖所选角色的全部长短文与四档位；必要时加 `--article` 查看正常文章的对应位置和其它同类标题。`check_scope=selected_roles` 的报告与总览只代表该范围，`unchecked_roles` 未复测，不能拼接旧版本截图宣称当前整套通过。定版时省略 `--roles` 做一次全量回归；全局令牌或共用渲染变化则扩大检查范围，工具不会自动判断影响面。`theme validate` 和完整布局覆盖检查不因局部截图而省略。

## 2. 实际看图：设计成立且没有阅读回退

看原尺寸组件局部和正常文章首中尾；全页缩略图只看节奏，不能用来判断细节。逐角色长短文案覆盖完整主题，正常文章判断真实阅读体验；文章没用到的角色在试样里补看，不能互相代替。

截图脚本自动生成 `component-overview.html` 和三张 `component-overview-*.png`，按角色分组、保留手机主验收的 357px 正文净宽与自然高度；实际打开这些总览，尤其并排看问答、案例、比较、总结，再看原尺寸局部与正常文章。HTML 可展开灰度辅助图，但不会移除图标或文字。已有匹配报告时可用 `--reuse-report <browser-report.json>` 在新目录只生成总览，省去重拍全部用例；历史 390px 报告仅作为明确标注的历史补充尺寸，不拉伸成当前手机证据。具体命令见契约。

按 [创作流程的评审与修订约定](theme-design-review.md#4-完成后评审实际画面并闭环修订)，同一次评审分别留下阅读与构图判断。风格辨识不等于正文表现：主题图案、角色标签和不同边框只能证明关联，构图通过还需在长文和文章中看见内容的落点、主副比例与连接。关键构图不足时回到对应参考改组织关系，优先于零散收口。工具不计算美观分，不设色块或异形门槛；声明目视通过须有实际范围，合理复用、安静角色和极简设计不因此判错。

| 检查对象 | 重点观察与修法 |
| --- | --- |
| 整体设计 | 原参考的关键构图是否仍可辨；联想有无转化为标题、容器、图片和细饰的关系，而不只是更多图标。不同角色用同一矩形换色或同一种纸片重复时，改组织关系；不能只关闭旧问题就宣布美观通过。用户要装饰性时，过度简化成线框也需要返工。 |
| 标题与编号 | 文字仍是阅读焦点；原稿带中文/数字编号时检查真实标题，不能只测额外徽章加短标题。多行标题不应绕着小图案下方的大块空列排版。保留原文，不缩小字号掩盖问题。孤字独行受字数、字号、标记占宽和内边距共同影响；截图工具标出实际末行单字供复核，不自动判失败。先按真实工作台尺寸看原稿全部标题，再看补充适配；需要修布局时检查同类标题，而非针对一个标题调几像素碰巧过关。不插硬换行、不擅自改标题，不把正常换行一概视为缺陷。 |
| 长正文与比较 | 不溢出仍可能太窄、断行频繁或出现长空列。装饰可只与标题同行，让正文恢复全宽；比较可用共同边界或中性标识表达关系，不必固定双栏，也不必变成时间线。 |
| 列表与步骤 | 普通圆点/编号与首行同行、续行对齐正文，优先使用 `marker_row`。确有分步卡片语义才上下分层。 |
| 装饰、线与间距 | 检查图案加载、等比缩放、手机尺度辨识度、线条收口和接缝；不与正文相交，不因透明画布或叠加内外边距多占大块空白。适合边线的低矮图案用 `ornament_rule`，较高图案另择合理位置，不能压扁。分隔线用 `rule`，不用空正文模拟。 |
| 图文与相框 | 用真实图片检查框与图片比例、边角装饰、图注和缩放；不要只测占位块。装饰不遮挡图片主体，不添加文章里没有的图片事实。无图原稿保持无图，图文角色另用授权测试图验证。 |
| 成篇节奏 | 遮住片头后，中段仍有主题辨识度；检查大容器是否连续堆叠、层级是否趋同。先保留强构图和招牌造型，分清细饰共享与整套结构套用，再调整造成重复的角色、使用频率和尺度；不全局删底色、去矩形或换成同一种细线纸页。正文、列表和图注保留安静区域，细饰不压过标题。 |

修订时保持同一文案、图片与宽度比较前后：解决了什么，有没有丢掉风格或带来新阅读问题。局部修复后复测受影响角色和文章；不要为凑轮次重做整套。真实表达能力不足时报告具体限制与近似范围，不把降级结果继续称为原目标。

## 3. 交付状态与微信边界

分别记录：结构/覆盖、浏览器几何、Agent 目视及评审方式、用户偏好、微信保存后实测。`21/21`、`findings=0`、`geometry=pass` 都不是美观评分，不输出无依据的还原率或满分。未做项保留待测，不把主代理检查称为独立评审；视觉反馈尚未解决时保留具体问题，不能用“用户偏好未确认”掩盖阅读或参考转译缺陷。测试宽度注明是视口宽度还是正文净宽，不能混用。

真实微信操作需要用户授权。具备条件后分别验证 API 与复制两条实际使用的路径：保存 → 重新打开 → 手机预览，覆盖主题小图案与正文配图。拿到 token、API 返回成功或粘贴瞬间正常，都不能替代保存后核对。记录对应主题/渲染/文章版本、路径、范围和证据；新增图案不能沿用旧版微信通过结论。

正常文章未覆盖的角色，在独立全组件试样中补测，使用真实图片并复用生产渲染与交付代码；不往正常文章塞组件，也不放宽生产组件预算。验收回执绑定主题和样张摘要，分别记录两条路径及保存、重开、手机结果，注明证据来自用户反馈还是实际截图；设备、浏览器和深色模式未核对时保留未测。

微信结构警告与实际缺陷分开判断。先定位对应内容：零行高若只用于无可见文字的图片容器或分隔线，不等于正文叠字；渐变凹口仍需核对边缘及提示涉及的深色模式。可见文字继承零行高、缺图、遮挡或异常空白应修复；保存后与手机正常的已测范围可记为通过并保留提示，不为消除警告牺牲已认可设计，也不隐藏警告或宣称其它环境均安全。未取得保存后 DOM 时，不把推测写成确定的微信过滤规则。

通过回执只属于被测试的版本、内容与环境；不修改核心自动报告的 `not_verified` 来伪造平台认证。新主题重新判断，主题或共享渲染/交付代码变化后按影响范围复测；已通过且未变化的版本无需为凑轮次重复盲测。

没有微信条件仍可交付完整本地设计，说明待测范围。不要为了测试自动发布、调用未授权付费服务或修改旧冻结稿。共享渲染修复后的刷新、重新定稿及异常草稿处理按主题契约和主 Skill 执行。
