# 自定义主题小型评测包

这是开发评测材料，不是 Skill 的新增执行步骤，也不进入用户安装包。现有 `skills/wechat-visual-director/evals/theme-pack-evals.json` 是行为场景目录；这里固定原始输入、证据锚点与复跑记录，不默认执行那 20 个场景。

## 先区分三个结论

| 结论 | 证据 | 不能替代什么 |
| --- | --- | --- |
| 工程与内容通过 | 生产校验、完整内容、版本绑定、当前版本浏览器检查 | 不能证明美观 |
| 视觉可交付 | 主尺寸可读；关键正文与参考相称；整篇有主次，弱角色未被强相框掩盖 | 不等于每个组件都惊艳，也不代表微信通过 |
| 有亮点 | 在可交付基础上，有具体值得保留的整体构图或细节表现 | 不能用图案数量、异形数量或主观总分代替 |

阅读、主题表现、成篇取舍分别记录 `pass / needs_revision / not_reviewed`，并给出实际图片位置和理由。符合需求约束、功能清楚与视觉表现分别判断：依据当前风格使用的字体、比例、空间、轮廓和细节观察效果，不按图案数量或形状分类放行。合理矩形、特色复用、安静角色不是自动扣分项。程序不会生成视觉分数或自动放行。

整体视觉可交付要求三个判断均有证据通过；任一未看保留未验证，明确不足保留待修。“有亮点”是额外判断，不把每轮更惊艳作为无限重试的理由。局部锚点只校准判断方法，不替整篇通过。

## 固定输入与保护边界

- `botanical-components`：三张植物组件参考、同一正常原稿，已运行的回归输入。
- `movie-components`：电影标题/正文组件参考、同一正常原稿，已运行的跨风格回归输入。
- `text-only-minimal`：纯风格描述、禁用额外图案；首轮已于2026-10-18审计，记录为阅读可用、视觉待修，转为回归输入。该单例同时包含无用户参考图与黑白极简约束，不能据此单独归因于输入方式。
- `text-only-citywalk`：城市漫游描述与原稿，不给风格参考图；2026-10-19已审计，记录为阅读可用、视觉待修，转为回归输入。不作为与极简用例的受控因果对照。独立测试照片不属于风格参考。
- `travel-components`：两张新的公开出游手帐组件截图，2026-10-19 独立审计通过本地创作验收，关键正文有局部亮点；2026-10-20 用户确认同版本全角色验收稿的 API 与复制保存、重开和手机预览正常。复制有未明细警告，未见格式错误。沿用城市漫游原稿，但参考和风格条件不同，不作为与纯描述用例的单变量对照；参考仅保留在本地输入，不纳入发行包。

原稿是项目自有公开演示内容，放在 fixtures。外部参考截图、测试照片和历史生成证据保存在被 Git 忽略的本地 artifacts，并用 SHA256 锁定；来源随输入保存。它们不是公共仓库已有资产：新机器缺少材料时明确报告缺失，不能伪报复现。需要迁移时，经授权单独转移本地评测目录，不将第三方图片自动纳入发行包。网页重截不是同一输入，应登记为新修订。

植物参考有原页面来源回执；电影历史截图的原页面 URL 未在旧输入中保存，已在用例标注来源缺口，仅保留本地回归用途，不推断授权状态。

`suite.json` 包含评审锚点与历史结果，**不可给创作 Agent 读取**。`prepare` 只把原始输入、当前 Skill 快照和隔离工具交给执行者；不会复制锚点、旧主题、历史结论或行为预期。必要的浏览器/工具安全说明可以读取，不因此放开历史成品或私有配置。具体失败案例留在评测记录，不逐例追加到创作 Skill；后续未见输入验证另选材料，同输入复跑只称回归。

## 最小使用方式

在仓库根目录运行（Python 3.10+，准备和对照页工具只用标准库，不调用模型或网络）：

```powershell
python evals/theme-creation/run.py inspect
python evals/theme-creation/run.py board --out artifacts/theme-eval-calibration
python evals/theme-creation/run.py prepare --case botanical-components --port 18589 --out artifacts/theme-eval-run
python evals/theme-creation/run.py verify --run artifacts/theme-eval-run
```

输出目录必须不存在，只允许在本仓库的 artifacts 或 .tmp 内创建；不覆盖旧证据。`board` 复制已锁定截图，生成本地静态页；先看图再展开定位，产品负责人可导出校准意见。四个局部定位已于 2026-10-15 由产品负责人在对话中认可，证据见 [校准记录](owner-calibration.json)。它们是带适用范围的判断锚点，不是整套主题金标或模型成功率；旧静态页保留生成时的待确认状态，不覆盖历史。

`prepare` 不创建对话、不启动服务、不安装主题、不自动花模型额度。它生成 `task-prompt.md`、输入锁和独立运行入口；明确获准后再新开对话，把生成的任务文本发给执行者。运行入口只连接指定本地端口，清除继承的业务配置，所有数据写本次 output；不能用于正式工作台升级。

`verify` 只核对冻结输入与 Skill 是否被改动，不验证主题质量。成品审计继续复用生产 `theme validate`、`theme review` 和截图脚本，不再实现第二套渲染/几何检查。核对主题 JSON、导出包、文章方案配置、HTML、截图 manifest/report 的绑定；保留作者自审与外部审计的区别。

准备目录根部的 `assessment.json` 由评审者填写，不交给创作 Agent；默认全部未验证。阅读、主题表现、成篇取舍分别附目视证据和理由，亮点另记；未知模型、token、费用保持 null。它是结构化回执模板，不是自动评分器。

## 每次改动到底跑多少

| 改动 | 默认最小验证 | 何时扩大 |
| --- | --- | --- |
| 文档链接、包装、入口措辞 | 文档与打包测试，不生成主题 | 实际改变模式路由/行为时选一个相关用例 |
| 某个角色的渲染或排字 | 固定长短试样和同类真实标题，按受影响角色局部截图 | 共用令牌/绘图/渲染器变化时扩大；定版全量回归 |
| 创作引导、自审判据 | 先用锚点校准判断，再选一个最相关用例做新会话 | 结果有争议时先区分偏好、输入、执行偏差；必要复跑，不预设固定多轮 |
| 准备发布、跨风格风险较大 | 按覆盖缺口选互补输入或尚未运行用例 | 不把一个样本推广为稳定成功率 |

一次创作仍按 Skill 的既有评审/修订边界完成，不因本评测包追加 Agent 流水线。出现同类失败先记录问题，不立即追加几十条提示或无限同题重做。记录模型、Skill 提交、工具与运行时间；拿不到实际 token/费用就写未知，墙钟时间不冒充成本。

微信 API/复制后的保存、重开和手机预览是独立交付检查：设计明显待修时无需先做；相关设计或发布路径改变后按范围验证。本地视觉通过不继承为微信通过。
