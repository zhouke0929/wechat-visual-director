# V1.0 Alpha.16 单进程与跨平台技术设计

## 1. 版本目标

Alpha.16 是本地运行与发行架构版本，不新增主题。它解决四类问题：

1. 历史任务在源码运行、持久化安装、卸载重装之间可发现、可备份、可恢复；
2. 工作台由 FastAPI 同一进程托管，用户运行时不再依赖 Next.js、pnpm 和 3000 端口；
3. Windows 安装过程固定前端构建工具版本，预构建发行包安装时不要求 Node.js；
4. 增加 macOS 技术预览版的安装、启动、诊断和卸载链路。

## 2. 已接受产品决策

- D320：Alpha.16 是运行时与跨平台架构版本，不扩充视觉主题。
- D321：先修复数据发现、备份和恢复，再迁移单进程工作台。
- D322：正式运行形态为一个 FastAPI 进程同时提供 API、静态工作台与本地资源。
- D323：普通用户安装预构建发行包时不在本机执行 pnpm 构建。
- D324：Windows 维持正式支持；macOS 在真实设备端到端验收前标记为技术预览。
- D325：基础排版和人工图片不依赖 Node.js；Wenyan 草稿交付是可选能力。
- D326：普通卸载保留 data、config 和不含密钥的 install-history.json。
- D327：Alpha.16 候选版验证前不修改运营电脑。
- D328：发布前至少通过 Windows 隔离安装回归、自动化测试与 macOS CI。
- D329：历史任务使用独立管理模式批量选择和二次确认；删除本地关联资产，但不操作公众号后台草稿或已发布文章。

## 3. 目标运行架构

```text
宿主 Agent / 用户
       |
       v
visual-director 启动器
       |
       v
FastAPI :8000
  ├─ /api/v1/*       业务 API
  ├─ /assets/*       工作台静态资源
  ├─ /tasks/*        SPA 路由回退
  └─ SQLite + image-assets + publication-assets
```

运行时不再启动 Next.js 服务，工作台与 API 同源，因此不再需要 CORS 端口白名单，也不会因为 3000 被占用而漂移到 3001。

## 4. 数据恢复契约

一个完整数据集必须同时包含：

- `visual-director.db`
- `image-assets/`
- `publication-assets/`

`data scan` 只读盘点当前数据根、安装历史记录及显式候选路径。`data recover` 遵守以下规则：

- 来源数据库必须通过 SQLite `quick_check`；
- 当前目标无任务时允许直接迁移；
- 当前目标已有任务时拒绝静默覆盖，只有显式 `--activate --yes` 才能切换；
- 切换前将目标完整复制到独立备份目录；
- 先复制到临时目录并复核，再替换目标数据集；
- 配置与 API Key 不参与数据迁移。

Alpha.16 不实现两份非空数据库的自动行级合并。该操作涉及任务、方案、图片、冻结版本和草稿操作的关联完整性，应作为后续独立能力设计。

## 5. 安装与卸载契约

- `install.json` 只描述当前有效安装；
- `config/install-history.json` 保存最近安装版本、数据根和卸载时间，不保存任何密钥；
- 默认卸载删除程序与运行时，保留 `data/`、`config/` 和安装历史；
- `--purge` 才删除业务数据和配置，并必须显式确认；
- 源码安装仅在缺少预构建静态工作台时调用固定版本 pnpm；发行包应自带静态产物。

## 6. 验收门槛

- 源码数据可被扫描并迁移到空的持久化数据根；
- 两份非空数据不会被静默覆盖，显式激活前生成可恢复备份；
- 仅启动一个服务进程即可打开首页、设置页、任务页和主题样册；
- 关闭 pnpm/Node 后，预构建安装仍可启动基础工作台；
- Windows 安装、升级、卸载、重装保留数据通过隔离回归；
- 历史任务可多选、全选和批量删除，数据库关联记录与本地资产同步清理；
- macOS CI 通过脚本语法、安装和 API/工作台冒烟测试；
- 真实 macOS 人工验收完成前，README 明确标注 Technical Preview。
