## 1. 本轮结果

仓库已从“可以手动运行的前后端项目”变为“可被 Agent 调用的薄 Skill”。Skill 不复制视觉规则，也不生成整段 HTML；它约束宿主 Agent 产出规范化 Markdown，并通过统一 CLI 调用现有核心程序。

```text
用户主题 / 资料 / Markdown
→ 宿主 Agent 按 wechat_article.v1 整理
→ scripts/visual-director.ps1
→ CLI 自动启动服务、预检并生成双方案
→ Web 工作台人工确认
```

## 2. 发行结构

```text
SKILL.md                         # Git/本地 Skill 根入口
agents/openai.yaml               # Codex UI 元数据
references/article-protocol.md   # Agent 写作与结构约束
references/cli-contract.md       # JSON、状态和退出码
scripts/install.ps1              # Windows 幂等依赖安装
scripts/visual-director.ps1      # 稳定 CLI 包装入口
scripts/persistent-launcher.ps1  # 固定安装目录入口与数据/配置环境注入
apps/api                         # 核心 API 与 CLI
apps/web                         # 本地人工评审工作台
```

OpenClaw 当前 Git 与本地目录安装均要求 `SKILL.md` 位于来源根目录，因此选择根 Skill，而不是只在仓库内增加 `skills/wechat-visual-director/`。

## 3. 安全边界

- Skill 和脚本不读取、写入或回显公众号 AppSecret、模型 Key、Cookie、Token。
- 创建任务默认自动规划，但不自动确认 finding、不自动选择方案、不自动创建公众号草稿。
- 相同原稿、账号和类型默认复用任务；只有明确增加 `--new-task` 才另建。
- 停止服务前校验 PID 与命令行身份；不匹配时退出码为 6，不终止未知进程。
- 图片模型缺失时允许上传、沿用或跳过，不用随机图片伪装成稿。

## 7. AI 规划模式澄清

首次真实公众号验收时，运行状态为 `mock_text_planner / deterministic_editorial_brief`，因此该轮组件规划使用确定性规则，没有产生 Qwen 调用费用。产品架构仍保留两层智能：

- 宿主 Agent 按 Skill 把主题和资料整理成规范 Markdown；
- 核心文本规划器在配置 Qwen BYOK 后理解全文并生成受控 EditorialBrief；未配置或调用失败时回退到规则规划；
- 确定性编译器始终负责组件白名单、结构保护与微信 HTML，任何模型都不得自由输出最终 HTML/CSS。

Alpha.2 已让 API 从 Git 忽略的 `.env.local` 持久化读取文本与图片 Provider 配置，并在 `doctor` 中分别报告 `ai_text_planning` 与 `rule_text_planning`，避免把规则模式误认为真实 AI 模式。

## 8. 持久安装与升级验收

验收要求：

- 同版本重复安装幂等；
- 从旧版本升级后，既有任务 ID、历史窗口、图片资产和私有配置继续存在；
- 依赖安装失败时不得切换 `install.json`；
- 安装与诊断输出不得包含 AppSecret 或模型 Key。

## 10. Alpha.7 多图片 Provider 适配

Alpha.7 将实验性的单一 Agnes 配置升级为稳定的内部生图契约与多 Adapter：

- `images_api + openai`：OpenAI GPT Image 及严格兼容接口；
- `images_api + ark`：火山方舟 Seedream；
- `images_api + extended`：保留旧 Agnes 等扩展中转协议；
- `gemini`：Google Nano Banana 原生 Interactions API；
- `manual` 与 `mock` 继续作为生产兜底和零额度验收模式。

工作台允许用户本人设置 Endpoint、Model ID、协议、尺寸和对应 Key。不同 Provider 的 Key 分开保存且永不回显；旧 `AGNES_*` 只读兼容，升级不会清空历史任务或立即破坏旧配置。自定义 Endpoint 必须使用 HTTPS，且拒绝本机、带凭据 URL 和局域网 IP。OpenAI 横图与公众号图片槽比例不一致时，由确定性图片处理器居中裁切为 4:3 或 16:9。

该版本没有把所有厂商强行包装成一个外部 OpenAI 协议。文章规划、图片槽、人工确认和发布链路只依赖内部 `generate(prompt, aspect_ratio)`；厂商字段差异留在 Adapter 内，避免“能连通但参数被静默忽略”的伪兼容。

首次本机安装验收暴露了混合进程问题：源码版旧 API 已在 8000 端口运行，但它动态读取到了新 `VERSION`，导致只比较版本号的 `doctor` 错把旧 Schema 判成 Alpha.7；新设置页收到 `image_provider_settings.v0.1` 后读取 `providers.images_api` 触发运行时错误。修复后 `/health` 同时暴露图片设置契约版本，持久安装的 `serve` 和 `doctor` 必须同时校验程序版本与契约版本；前端也会在旧 Schema 下显示明确的“停止旧服务”提示，不再进入未定义属性。已用“相同版本号、旧契约”的两项回归测试覆盖该场景。

## 11. Alpha.8 端到端信息图与质量归因

D203–D208 将正文图片拆成两条明确链路：

- 普通配图生成无文字语义插画，不再用固定卡片重复正文；
- 结构信息图把原文标题和 2–4 个节点作为锁定文案交给模型，由模型完成最终版式、图标、插画和文字；
- EditorialBrief 的视觉隐喻、风格家族、色板与气质完整进入 Provider 提示词，不再只按文章类型套固定配色；
- 本机存在 Tesseract 中文 OCR 时执行逐项严格匹配；OCR 缺失或不能完整证明一致时，工作台要求运营逐项核对并勾选，未经确认不得采用；
- 确定性叠字保留为“不调用模型”的显式保底方案，并修复三节点布局、字号自适应和文字溢出；
- 每个候选保存模型原始输出和最终候选，工作台可打开原图，避免把模型问题与后处理问题混为一谈。

真实验收稿改用浙江省教育考试院 2026 年志愿填报通知、教育部招生体检指导意见和阳光高考公开问答，覆盖规则数字、来源层级、二维核对表、流程清单和风险复核，避免短样稿信息不足造成的错误归因。

## 12. Alpha.9 快速审核工作台

Alpha.9 把内部 Beta 的默认操作收敛为“选方案—审图片—创建草稿”：

- 选定方案后默认进入配图审核，组件换型标记为可选微调；
- 支持一次触发所有空图片槽，并按顺序调用 Provider；
- 新候选自动进入全屏审核，可缩放、查看原始输出并与锁定原文对照；
- OCR 未完整通过时，以“文字无误，采用此图”作为唯一的显式人工确认，后台文字门禁保持不变；
- 采用后自动进入下一张待审核候选，减少长页面上下滚动；
- 工作稿继续自动保存；本机 Wenyan 就绪时，最终主按钮一次完成冻结版本与创建微信公众号草稿，最终群发仍由人工在公众号后台完成。
