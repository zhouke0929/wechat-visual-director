# Alpha.11 真实运营观察表

该表用于 Alpha.11 发布后的 3–5 篇真实公众号文章观察。目标不是考核运营，而是判断问题来自组件供给、原稿结构还是 Agent 选择策略。

## 单篇记录

| 字段 | 记录内容 |
|---|---|
| 日期与样本编号 | 例如 `2026-08-01 / OPS-01` |
| 文章类型 | 数据政策 / 教程步骤 / 观点趋势 / 产品介绍 |
| 大致篇幅 | 短 / 中 / 长 |
| 系统推荐主题 | 六套主题之一 |
| 最终使用主题 | 六套主题之一；若手动改选请注明 |
| 自动采用组件 | 组件类型和数量 |
| 人工修改位置 | 组件、图片、封面、正文结构或其他 |
| 修改原因 | 不好看 / 不匹配语义 / 信息不够突出 / 结构识别遗漏 / 其他 |
| 操作时间 | 从任务生成到写入草稿箱的大致时间 |
| 草稿结果 | 成功 / 重试成功 / 失败 |
| 关键截图 | 只保存脱敏后的局部截图 |
| 运营结论 | 可直接发布 / 小改可用 / 需要较多修改 |

## 阶段汇总

完成 3–5 篇后统一回答：

1. 默认主题是否经常被改选；
2. 哪些组件最常被删除、替换或补充；
3. 原稿是否经常因为缺少列表、H3、表格或引文而无法绑定组件；
4. Agent 是否已经识别真实结构，但没有选择适合的组件；
5. 单篇人工处理时间相较旧工作流是否下降；
6. 下一轮优先级应落在组件供给、结构整理还是选择策略。

公众号密钥、模型 Key、完整内部稿件和未脱敏品牌资产不得写入该表或提交到公开仓库。
