## 1. 背景

公众号视觉主编已经在真实运营环境完成文章生成、人工评审与微信公众号草稿交付，并有文章正式发布。当前主要风险已从“视觉编译器是否可用”转为“陌生用户能否稳定安装、启动和完成本机配置”。

现有 Skill 采用“薄 Skill + FastAPI 核心 + Next.js 工作台 + 可选 Wenyan”的结构。Skill 指令本身只有约 12KB，不是主要负担；运行层每个版本会重复安装 Python 虚拟环境与前端依赖，工作台又使用 Next.js 开发模式启动，造成首次安装慢、冷启动慢、历史版本占用大，以及在 Trae、WorkBuddy 等不同宿主中出现命令、端口和运行版本问题。

微信公众号和图片 Provider 还需要人工配置。图片 Provider 已有本地设置页，但微信公众号仍主要依赖配置文件和文字说明。用户若把 GitHub 链接交给 Agent，Agent 可以完成部分安装动作，却不一定能替用户登录公众号后台、查找 AppID/AppSecret、配置 IP 白名单或判断哪些步骤必须人工完成。

## 2. 核心定义

### 2.1 配置属于本机，不属于对话

“首次配置”只表示当前电脑第一次建立持久安装和能力配置，不表示用户第一次进入某个 Agent 对话。

换对话、重启 Agent 或更换宿主后，系统必须通过稳定启动器和 `doctor --json` 读取本机真实状态：

```text
未安装       → 找不到稳定启动器或安装清单
已安装未配置 → 核心可运行，但可选能力尚未配置
部分就绪     → 排版可用，生图或微信草稿能力缺失
全部就绪     → 所选能力均通过本机检查
需要复核     → 历史配置存在，但网络、版本或外部服务状态发生变化
```

Agent 不得因为进入新对话而重复安装、清空配置或再次索要密钥。设置页也不保存单一的“首次配置完成”布尔值，而是动态展示每项能力的当前状态。

### 2.2 三种使用模式

用户首次打开本机能力设置时选择目标模式，选择只影响引导范围，不限制以后升级能力：

1. **仅排版**：规范 Markdown、生成双方案、人工评审、复制正文和下载交付包；
2. **排版 + 生图**：在仅排版基础上配置图片 Provider；
3. **完整交付**：继续配置 Wenyan、公众号凭据和 IP 白名单，允许创建公众号草稿。

任何可选能力未就绪都不得阻断基础排版。

设置页采用渐进式展开：仅排版不展示任何 API 配置；排版 + 生图只展示图片配置；完整交付展示图片与微信公众号配置。用户切换目标后，相关配置紧随目标选择区域出现，不要求理解当前目标用不到的能力。

## 3. 产品目标

### 3.1 本轮目标

- 用户把固定 GitHub Release 链接交给具备终端能力的 Agent 后，Agent 能按唯一入口完成安装或升级；
- 新对话能够发现已安装 Skill，并复用本机任务、配置和稳定启动器；
- 用户在浏览器内看懂当前电脑具备哪些能力、缺少什么，以及下一步由谁操作；
- 微信公众号凭据只由用户在本地页面填写，不进入聊天内容和命令行；
- 公众号连接验证不创建草稿，创建草稿继续保留明确人工门禁；
- 冷启动、磁盘占用和端口冲突显著降低；
- 安装或启动失败时，Agent 能读取结构化错误并给出单一修复动作。

### 3.2 非目标

- 不建设云端账号、团队权限、计费或 SaaS 控制台；
- 不自动完成公众号最终群发；
- 不要求 Agent 登录或操作用户的微信公众号后台；
- 不在本轮增加新主题或无边界扩展组件；
- 不同时承诺 Windows、macOS、Linux 的免依赖安装包；
- 不把 AppSecret、图片 Key 或其他凭据上传到项目服务器或 GitHub。

## 4. 用户与职责边界

| 参与者 | 负责 | 不负责 |
|---|---|---|
| 运营用户 | 选择目标模式、填写本地凭据、配置公众号后台白名单、确认方案和草稿 | 执行 Python/Node 调试命令 |
| 宿主 Agent | 下载安装、调用稳定启动器、读取状态、生成规范稿与 EditorialBrief、打开工作台 | 读取或代填密钥、替用户确认发布 |
| 本地核心 | 校验配置、渲染方案、保存任务、生成诊断、调用已配置 Provider | 登录公众号后台、猜测用户凭据 |
| 微信公众号/Wenyan/图片 Provider | 提供外部接口能力 | 保证本地工作台始终可用 |

## 5. 信息架构

### 5.1 本机能力设置页

设置页由一个总览和三个能力卡组成：

```text
本机能力总览
├── 基础排版
│   ├── 核心版本
│   ├── 工作台状态
│   └── Skill 注册状态
├── AI 生图（可选）
│   ├── 人工上传 / Mock / Images API / Gemini
│   ├── 本地 Key 配置
│   └── 连接测试
└── 微信草稿（可选）
    ├── Wenyan 安装状态
    ├── AppID / AppSecret 本地配置
    ├── 公网出口 IP 与白名单指引
    ├── 连接检测
    └── 创建测试草稿（独立人工动作）
```

每张卡只使用四种状态：`已就绪`、`需要配置`、`需要复核`、`暂不可用`。页面必须解释缺失能力不会影响哪些已就绪功能。

### 5.2 设置入口

- 全新安装成功后自动打开本机能力设置页；
- 首页保留“本机设置”入口；
- 任务页在生图或微信能力缺失时显示针对性入口；
- 新对话只运行 `doctor`，只有发现缺失项时才建议打开对应设置卡；
- 已全部就绪时，Agent 直接创建文章任务，不重复展示向导。

## 6. 核心流程

### 6.1 GitHub 链接交给 Agent

```text
用户提供固定 Release 或仓库链接
→ Agent 读取 INSTALL_FOR_AGENT.md
→ 查找稳定启动器
→ 已安装：判断是否需要升级
→ 未安装：调用唯一 bootstrap 入口
→ 安装器返回结构化 JSON
→ Agent 运行 doctor
→ 打开设置页或直接创建任务
```

安装器必须幂等。重复执行不得清空 `data/`、`config/`、`runtime/`，也不得把临时克隆目录作为后续运行目录。

### 6.2 新对话继续使用

```text
新对话触发 wechat-visual-director
→ 查找固定 launcher
→ doctor
→ 全部就绪：直接处理文章
→ 部分就绪：继续处理文章，仅提示缺失的可选能力
→ 版本不一致：停止旧服务并从稳定入口恢复
→ 未安装：进入安装流程
```

### 6.3 微信公众号绑定

1. 系统检查 Wenyan 是否安装并显示兼容版本；
2. 用户进入微信公众平台的开发者后台，在开发接口管理的账号开发信息中获取 AppID，并生成或重置 AppSecret；具体栏目名称以微信当前页面为准；
3. 用户在本地页面填写 AppID 与 AppSecret；页面只显示是否已配置，保存后不回显原值；
4. 页面显示当前公网出口 IP 和复制按钮，并说明需要用户进入微信开发者后台配置白名单；
5. 用户完成后台操作后点击“检测连接”；
6. 系统只验证凭据、网络和接口可访问性，不创建草稿；
7. 检测通过后标记“微信草稿已就绪”；
8. 若用户需要端到端验证，再独立点击“创建测试草稿”，并明确说明该动作会写入公众号后台。

“清除凭据”不得作为普通保存选项展示。它位于折叠的高级操作中，产品文案使用“解除本机绑定”，执行前二次确认，并说明该动作只删除本机副本，不会在微信侧重置 AppSecret 或影响公众号。

公网 IP 变化时，系统将微信能力标记为“需要复核”，但不删除已有凭据。

### 6.4 失败恢复

错误页面和 CLI JSON 必须同时提供：

- 稳定错误码；
- 用户可理解的中文原因；
- 是否可重试；
- 唯一建议动作；
- 日志或诊断包路径；
- 已就绪能力仍可使用的说明。

Agent 不得在端口冲突、版本不一致或发布结果未知时自行绕过稳定入口。草稿结果为 `unknown` 时仍先由用户去公众号后台核对，禁止自动重试。

## 8. 运行架构演进

### 8.1 第一阶段：稳定现有双进程

- 安装时执行生产构建；
- 运行时使用固定构建，不再启动 Next.js 开发服务器；
- 正确注入当前 API 地址和应用版本；
- 只保留当前版本与可回滚的上一版本；
- 将依赖检查、端口检查和版本检查统一放在稳定启动器中。

### 8.2 第二阶段：单进程发行

- 将工作台编译为静态资源；
- 由 FastAPI 同源提供页面和 API；
- 去除浏览器 CORS、双端口和前后端版本错配；
- 使用 GitHub Actions 生成 Windows 发行资产；
- bootstrap 只负责下载、校验、解压、注册 Skill 与启动，不在用户电脑安装开发依赖。

## 9. 安全要求

- 设置接口只接受本机回环请求和显式设置意图；
- 密钥只写入 Git 忽略且位于程序版本目录之外的私有配置；
- 页面、日志、doctor、诊断包和 Agent 输出不得包含密钥原文；
- 安装器不得上传现有任务、图片、数据库或配置；
- 旧版本清理只删除程序版本目录，不删除数据、配置和运行日志；
- 连接检测不得创建公众号草稿或消耗图片生成额度，除非用户明确执行对应测试动作。

## 10. 验收标准

### 10.1 产品验收

- 用户换新对话后不会被要求重新安装或重新配置；
- 仅排版用户无需理解图片 Key、公众号凭据和 IP 白名单；
- 完整交付用户能够分辨“本地已保存凭据”“连接已验证”“草稿已创建”三种状态；
- 所有需要登录公众号后台的步骤都明确标记为人工操作；
- 外部能力失败时，基础排版、复制正文和下载交付包继续可用。

### 10.2 技术验收

- OpenCode、WorkBuddy、Trae 各完成一次固定 Release 的全新安装；
- 三种宿主均只使用稳定 launcher，不运行临时目录中的 `pnpm dev` 或系统 uvicorn；
- 安装、升级、换对话三条路径的数据和配置保留率为 100%；
- Alpha 第一阶段冷启动目标不超过 15 秒，暖启动目标不超过 3 秒；
- 单进程发行阶段冷启动目标不超过 8 秒；
- 第一阶段只保留两个程序版本，安装目录不再无限增长；
- 单进程 Windows 发行包安装后程序体积目标不超过 250MB；
- 所有错误场景均能生成脱敏诊断结果。

## 11. 评测样本

至少覆盖以下场景：

1. 全新 Windows 电脑，没有 Python、Node、pnpm；
2. 已安装旧版本且存在历史任务、图片和本地密钥；
3. 换 Agent 新对话，但本机安装完整；
4. 只需要排版，不配置任何外部 Provider；
5. 图片 Provider 已配置，微信草稿未配置；
6. 微信凭据正确但 IP 未加入白名单；
7. 3000 或 8000 端口被其他程序占用；
8. 旧服务仍在运行且版本不一致；
9. 微信草稿返回 `unknown`；
10. 无网络或 GitHub 下载中断后的安全重试。
