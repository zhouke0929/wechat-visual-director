# V1.0 规范化文章输入协议

- 状态：V1.0-alpha.1 评审稿
- 日期：2026-07-22
- 适用入口：OpenClaw、Claude Code、其他 Agent、独立工作台
- 协议定位：Agent 与视觉编译器之间的内容交换协议，不是运营必须手写的表单

## 1. 目标

同一篇内容无论由哪个 Agent 生成，都应被视觉编译器稳定解析；输入结构较弱时允许安全修复和视觉降级，但不得为了排版改写事实、数字、来源、观点和结论。

协议约束的是文章内容结构，不约束最终视觉组件。宿主 Agent 不应直接指定 HTML、CSS、组件变体或颜色；这些由视觉编译器结合文章语义、品牌配置和最近五篇历史决定。

## 2. 最小合法稿件

稿件必须满足：

- UTF-8 编码，大小不超过 2 MiB；
- 能从 frontmatter `title` 或唯一 H1 得到文章标题；
- 标题之外至少有一个正文内容块；
- 不包含 API Key、Cookie、Token 或公众号密钥；
- 不使用脚本、表单、外部样式表或用于排版的自定义 HTML。

最小示例：

```markdown
---
schema_version: wechat_article.v1
title: 高考志愿填报前，先看懂这三个隐藏规则
article_type: tutorial_steps
summary: 用三个步骤帮助家长核对分数、位次和专业限制。
---

# 高考志愿填报前，先看懂这三个隐藏规则

志愿填报不是一次“凭感觉排序”，而是一组需要逐项验证的决策。

## 第一步：核对分数、位次和选科

先以省级教育考试院公布的数据为准，记录总分、位次、选科组合和各科成绩。

1. 保存官方查询页面或截图；
2. 记录一分一段表中的准确位次；
3. 标记单科成绩可能触发的专业限制。

> 数据来源：省级教育考试院当年公开信息。
```

## 3. Frontmatter 字段

| 字段 | 必需 | 说明 |
|---|---:|---|
| `schema_version` | 推荐 | V1.0 固定为 `wechat_article.v1`；缺失时仍可预检，但记录兼容模式 |
| `title` | 推荐 | 与 H1 保持一致；冲突时进入预检提醒，不静默覆盖 |
| `article_type` | 否 | 技术兼容字段，产品界面称“内容结构”；可填 `data_policy`、`viewpoint_trend`、`tutorial_steps`、`lively_growth`，或省略后自动识别 |
| `summary` | 否 | 文章摘要，不超过 120 个汉字；不能包含正文未支持的新结论 |
| `author` | 否 | 仅用于草稿元数据；微信公众号适配器继续执行实际长度限制 |
| `cover` | 否 | 本地相对路径或受支持 URL；缺失不阻断排版，但阻断自动创建公众号草稿 |

Agent 不得在 frontmatter 中写入模型名称、会话历史、内部提示词、密钥或用户隐私信息。

> 历史说明：该段最初编写时微信公众号适配器尚未实现。当前 Alpha 已提供可选的本机 Wenyan
> 真实草稿适配器；只有运行时检查显示发布器就绪且用户在工作台确认后才会调用微信接口。

## 4. 标题层级

- 全文使用一个 H1，表示文章标题；
- H2 表示不可被组件吞并的主章节；
- H3 表示章节内的概念、问题、步骤或小主题；
- H4–H6 仅在确有从属关系时使用；
- 不使用加粗段落冒充主章节；
- 不为了视觉编号而给所有短句增加标题标记；
- 标题自带“一、”“第 1 步”“01”等编号时保留原编号，视觉编译器不得重复编号。

结构不明确时，视觉编译器优先降级为普通标题和正文，不通过猜测重组文章。

## 5. 内容块约定

### 5.1 段落

一个自然语义段落连续书写，不用多余空格或硬换行模拟视觉布局。视觉留白由渲染器控制。

### 5.2 列表与步骤

- 并列信息使用 `-`；
- 有顺序的操作使用 `1.`；
- 至少两个并列项才使用列表；
- 不用多个 emoji 行模拟列表。

### 5.3 问答

问答模块使用 H3 问题标题加紧随其后的回答段落。只有真实问题才使用问号，不为了触发组件制造问题。

### 5.4 概念解释

概念标题应明确表达“什么是”“概念”“定义”或等价语义，正文紧随定义。主章节、核心功能、痛点、步骤和行动项不得伪装成概念解释。

### 5.5 数据与来源

- 数字、政策、招生规则和引用尽量附带来源；
- 来源使用 `> 数据来源：`、`> 资料来源：` 或 `> 规则来源：`；
- 来源文字只作为辅助元信息，不作为结论、证据卡标题或大字号正文；
- Agent 不确定来源时明确标记“待人工核验”，不得编造链接。

### 5.6 表格

真实二维数据使用标准 Markdown 表格。仅用于视觉布局的信息不得写成表格。

### 5.7 图片

已有图片使用标准 Markdown：

```markdown
![展示历年位次变化的折线图](./assets/rank-trend.png)
```

alt 文本必须描述图片语义，不能只写“图片”“配图1”。没有图片时不插入随机占位 URL；视觉编译器根据正文另行创建图片槽，用户可生图、上传或跳过。

## 6. 内容安全边界

Agent 可以：

- 按用户要求生成、整理和润色初稿；
- 将明确并列内容转换成标准列表；
- 将明确主章节整理为 H2；
- 保留用户提供的事实、数字和来源。

Agent 不得：

- 为了适配组件创造概念、因果、结论、案例或数据；
- 把短场景句自动标记为结论；
- 将 H2 主章节塞进概念卡、证据卡或时间线；
- 混入上一轮文章主题或会话残留；
- 生成用于排版的 HTML/CSS；
- 自动生成或替换品牌 CTA、二维码和公众号凭据。

## 7. 容错与降级

视觉编译器继续保留现有 Preflight：

- 唯一结果的机械问题可以自动修复并记录；
- 标题冲突、层级歧义和疑似内容污染进入 `REVIEW`；
- 空稿、无法确定标题、敏感凭据和非法输入进入 `BLOCK`；
- 结构较弱但内容安全时允许生成受限方案，强组件降级为普通正文；
- 图片、封面和 CTA 缺失可以先排版，但在自动创建公众号草稿前必须解决。

## 8. Agent 输出要求

宿主 Agent 完成写作后应：

1. 将最终 Markdown 保存为临时 UTF-8 文件；
2. 不在聊天中暴露本地密钥和私有配置；
3. 调用视觉主编 CLI 创建任务；
4. 如果预检返回 `BLOCK`，根据明确 finding 修复原稿后重新创建任务；
5. 如果返回 `REVIEW`，打开工作台让用户处理，不自行绕过人工确认；
6. Alpha 默认先生成本地冻结版本；本机 Wenyan 就绪时可在用户确认后创建公众号草稿，但不执行最终群发。

## 9. 产品评审点

产品负责人只需确认：

- H1/H2/H3 的约定是否符合运营常见写作方式；
- 四种文章类型是否继续满足首版范围；
- 来源、图片和封面缺失时的降级是否合理；
- 协议是否限制了正常表达，而不是只限制错误排版行为。
