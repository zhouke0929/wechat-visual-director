# V1.0 本机能力设置与轻量安装技术设计

- 文档状态：技术方案已接受，进入实现
- 日期：2026-08-05
- 对应 PRD：`V1.0本机能力设置与轻量安装体验PRD.md`
- 对应产品决策：D300–D314
- 首个实现版本：v0.1.0-alpha.15
- 实现进度：Slice A–D 已完成并通过保留数据卸载重装、完整清除和生产进程回归；Slice E 待实施

## 1. 技术目标

Alpha.15 在不改写视觉编译、任务数据库和微信兼容渲染器的前提下完成四件事：

1. 建立与对话无关的本机能力状态模型；
2. 在本地工作台完成图片和微信公众号能力的引导配置；
3. 将发行工作台从 Next.js 开发模式切换为可版本校验的生产模式；
4. 统一 Agent 安装、升级、诊断和故障恢复入口。

Alpha.16 再将前端静态化并合并为 FastAPI 单进程。本设计不会为了提前实现单进程而阻塞 Alpha.15 的首次使用体验。

## 2. 现状与约束

### 2.1 可复用能力

- FastAPI 已提供任务、图片设置、冻结版本、交付包和 Wenyan 草稿接口；
- Next.js 工作台已完成本地图片 Provider 设置和人工评审；
- `settings.py` 已能原子更新 Git 忽略的本地 `.env.local`；
- CLI 已有稳定启动器、版本检查、进程记录、`doctor` 和结构化错误；
- 持久目录已把程序版本与 `data/`、`config/`、`runtime/` 分离；
- Wenyan Publisher 已能识别缺少凭据、IP 白名单、无效密钥和未知结果。

### 2.2 当前瓶颈

- 每个版本重复包含约 335MB 前端依赖和约 59MB Python 虚拟环境；
- 本机五个历史版本合计约 2.5GB；
- CLI 使用 `next dev`，首次启动包含运行时编译；
- `NEXT_PUBLIC_API_BASE_URL` 会在构建期固化，曾出现生产页面仍指向旧测试端口；
- 图片设置与微信设置没有统一的能力总览；
- 微信凭据主要依靠人工编辑配置文件；
- Agent 安装说明分散在 README、SKILL、Release 和历史文档中。

## 3. 总体架构

### 3.1 Alpha.15

```text
宿主 Agent
    │
    ▼
stable launcher / CLI
    ├── install / upgrade / doctor / setup status
    ├── FastAPI :8000
    └── Next.js production server :3000
            │
            └── runtime-config.js → 当前 API 地址与版本

持久目录
    ├── data/       任务、图片、SQLite
    ├── config/     私有凭据与设置偏好
    ├── runtime/    PID、日志、诊断
    └── versions/   current + previous
```

### 3.2 Alpha.16 目标

```text
stable launcher
    └── 单个本地应用 :8000
            ├── FastAPI /api/v1
            └── 静态工作台 /
```

Alpha.16 前端默认使用同源 `/api/v1`，从结构上消除 CORS、双端口和构建期 API 地址问题。

## 4. 本机能力状态模型

### 4.1 状态枚举

每项能力独立计算，不保存“首次配置完成”布尔值：

```text
ready             已就绪
configuration     需要用户配置
review_required   历史配置存在，但外部状态需要重新确认
unavailable       当前环境无法使用
checking          正在执行用户主动发起的连接检测
```

### 4.2 能力对象

```json
{
  "id": "wechat_draft",
  "state": "configuration",
  "required": false,
  "summary": "需要配置公众号凭据和 IP 白名单",
  "reason_code": "wechat_credentials_missing",
  "next_action": {
    "kind": "open_local_page",
    "url": "/settings/wechat"
  }
}
```

`summary` 和 `reason_code` 可被 Agent 安全读取；响应不得包含 AppID、AppSecret、API Key、Cookie 或 Token。

### 4.3 设置偏好

用户选择的目标模式写入：

```text
config/setup-preferences.json
```

Schema：

```json
{
  "schema_version": "setup_preferences.v0.1",
  "target_mode": "typeset_only | images | full_delivery",
  "updated_at": "ISO-8601"
}
```

目标模式只决定向导展示和 `required` 标识，不改变真实能力检测结果。

## 5. API 设计

### 5.1 能力总览

```http
GET /api/v1/settings/capabilities
```

返回：

```json
{
  "schema_version": "local_capabilities.v0.1",
  "target_mode": "full_delivery",
  "capabilities": {
    "core": {},
    "host_skill": {},
    "image_generation": {},
    "wechat_draft": {}
  },
  "setup_complete_for_target": false
}
```

该接口只聚合本地状态，不主动访问图片供应商、IP 查询服务或微信接口。

### 5.2 设置目标模式

```http
PUT /api/v1/settings/setup-preferences
Content-Type: application/json
X-Settings-Intent: local-operator

{"target_mode":"full_delivery"}
```

继续复用 `_local_settings_request`：只允许回环地址和显式本地设置意图。

### 5.3 微信设置快照

```http
GET /api/v1/settings/wechat-publisher
```

返回：

```json
{
  "schema_version": "wechat_publisher_settings.v0.1",
  "wenyan": {
    "installed": true,
    "version": "2.0.11",
    "compatible": true
  },
  "credentials": {
    "app_id_configured": true,
    "app_secret_configured": true,
    "source": "local_config",
    "managed_by_environment": false
  },
  "connection": {
    "status": "not_tested",
    "last_checked_at": null,
    "reason_code": null
  },
  "config_file": "脱敏后的本地路径",
  "warnings": []
}
```

AppID 也不回显原值，避免诊断截图和录屏泄漏账号标识。

### 5.4 保存微信设置

```http
PUT /api/v1/settings/wechat-publisher
Content-Type: application/json
X-Settings-Intent: local-operator

{
  "app_id": "可选的新值",
  "app_secret": "可选的新值",
  "clear_credentials": false
}
```

约束：

- 新值仅写入 `VISUAL_DIRECTOR_ENV_FILE` 指向的私有配置；
- 进程环境已托管任一字段时，页面对相应字段只读；
- 保存只做本地格式校验和热加载，不访问微信接口；
- 新值与清除操作不可同时提交；
- 成功响应只返回布尔配置状态。

### 5.5 微信连接检测

```http
POST /api/v1/settings/wechat-publisher/probe
X-Settings-Intent: local-operator
Idempotency-Key: <uuid>
```

检测由新的 `WechatConnectionProbe` 适配器完成：

1. 检查 Wenyan 兼容版本；
2. 检查本机凭据是否存在；
3. 调用微信公众号基础连接能力验证凭据、网络与 IP 白名单；
4. 立即丢弃返回的短期令牌，不写入日志、数据库和响应；
5. 只保存时间、结果和稳定错误码。

该接口不得上传图片、创建草稿或触发最终发布。外部接口细节封装在 Adapter 内，业务层和前端不依赖供应商原始响应结构。

稳定错误码：

```text
wenyan_not_installed
wenyan_version_unsupported
wechat_credentials_missing
wechat_credentials_invalid
wechat_ip_not_whitelisted
wechat_network_unavailable
wechat_probe_timeout
wechat_probe_unknown
```

### 5.6 公网出口 IP

```http
POST /api/v1/settings/network/public-ip-probe
X-Settings-Intent: local-operator
```

- 只在用户点击“检测公网 IP”时请求外部 IP 查询服务；
- 不在页面加载、doctor 或 Agent 新对话中自动调用；
- 服务地址做成可替换 Adapter，并设置短超时；
- 查询失败时允许用户从浏览器访问外部页面或手工填写后台白名单；
- IP 仅展示与复制，不写入公众号凭据文件。

该结果只是“当前网络观测值”，不能声称已存在于公众号白名单。真正就绪仍以微信连接检测成功为准。

同一 Adapter 暴露稳定 CLI：

```powershell
visual-director.cmd network public-ip --json
```

Agent 只有在用户选择完整交付、明确要求配置微信草稿，或设置页返回 `next_action=probe_public_ip` 时才调用。CLI 与工作台按钮返回同一 Schema：

```json
{
  "ok": true,
  "schema_version": "public_ip_probe.v0.1",
  "public_ip": "203.0.113.10",
  "observed_at": "ISO-8601",
  "next_action": "add_to_wechat_allowlist",
  "settings_url": "http://127.0.0.1:3000/settings/wechat"
}
```

CLI 不使用 `ipconfig` 推断公网地址，也不允许宿主 Agent 临时选择未知 IP 查询站点。普通写稿、换新对话、`doctor` 和服务启动不得隐式执行该外部请求。

## 6. 前端设计

### 6.1 页面与渐进式展开

```text
/settings             本机能力总览、图片配置与微信草稿配置向导
```

Alpha.15 先在同一页面按目标渐进展开，避免路由跳转和无关配置干扰：`typeset_only` 只显示已就绪提示，`images` 展开图片配置，`full_delivery` 展开图片与微信配置。后续只有在单页复杂度再次超过运营认知负担时，才拆分子路由。

### 6.2 微信向导步骤

1. **发布组件**：展示 Wenyan 状态和兼容版本；
2. **公众号凭据**：引导用户从微信开发者后台的开发接口管理获取，本地密码输入框只显示“已配置/未配置”；
3. **IP 白名单**：用户主动检测当前公网 IP，展示后台操作说明；
4. **连接检测**：不创建草稿；
5. **完成**：显示微信草稿已就绪，并解释最终发布仍需人工确认。

解除绑定属于高级危险操作：前端不展示“保存时清除凭据”复选框，而是在折叠区显示“解除本机绑定”，二次确认后才向既有 `clear_credentials` 后端字段提交。

Alpha.15 不允许 Web API 直接执行全局 `npm install`。缺少 Wenyan 时提供：

- “复制安装命令”；
- “交给 Agent 安装”的明确提示；
- CLI 后续可增加显式 `setup wenyan --install --json`，但不得在普通 `doctor` 中静默安装。

### 6.3 可恢复交互

- 刷新页面后从服务端能力状态继续当前步骤；
- 保存失败不清空输入框以外的已完成状态；
- 外部检测超时不删除凭据；
- 页面显示“仍可使用仅排版/人工上传”等可用能力；
- 所有外部写操作均有忙碌态和防重复提交。

## 7. Next.js 生产运行方案

### 7.1 构建

安装器在版本目录完成：

```text
pnpm install --frozen-lockfile
pnpm build
```

只有构建成功才允许切换 `install.json.current_version`。

### 7.2 运行时配置

删除固定 `.env.production.local` API 地址。浏览器统一请求工作台同源的
`/api/backend/*`，由 Next.js 运行时代理读取 `VISUAL_DIRECTOR_API_BASE` 并转发到
FastAPI。这样 API 地址不会写入构建产物，也不再依赖某个固定前端端口的 CORS
白名单；自定义端口与不同宿主环境可复用同一份生产构建。工作台健康检查继续
校验运行版本和设置 Schema。

### 7.3 启动

CLI 将：

```text
pnpm dev → pnpm start --hostname 127.0.0.1 --port 3000
```

进程识别、停止规则和日志记录同步从 `pnpm dev` 更新为生产服务器特征。CLI 继续阻止复用版本不匹配的页面。

## 8. 安装、升级与清理

### 8.1 唯一 Agent 入口

仓库根新增 `INSTALL_FOR_AGENT.md`，只描述：

```text
查找稳定 launcher
→ 已安装则 doctor / upgrade
→ 未安装则执行 scripts/bootstrap.ps1
→ 读取最终 JSON
→ doctor
→ 根据 next_action 打开设置页或创建样例任务
```

README 保留面向人的概览，不再重复完整故障树。SKILL 只在首次使用段引用安装文档。

### 8.2 bootstrap

`scripts/bootstrap.ps1` 负责：

- 判断全新安装或升级；
- 升级前调用旧稳定入口 `stop --json`；
- 调用版本内 `install.ps1`；
- 运行新稳定入口 `doctor --json`；
- 成功后返回 `review_url` 或 `settings_url`；
- 失败后返回错误码、日志路径和诊断包路径；
- stdout 只输出最终 JSON，进度写入 stderr。

Alpha.15 bootstrap 在完整仓库或 Release 解压目录运行；Alpha.16 再支持从固定 Release URL 下载预构建资产。

### 8.3 历史版本清理

新版本安装成功后只保留：

```text
current_version
previous_version
```

删除前必须验证：

- 目标位于 `<install_root>/versions/`；
- 不是 current 或 previous；
- 不包含 `data/`、`config/`、`runtime/` 的解析路径；
- 旧服务已经停止。

清理失败不回滚新版本，只返回 `old_versions_cleanup_failed` 警告和待清理路径；不得对未知路径执行递归删除。

## 9. CLI 与 Skill 契约

### 9.1 doctor 扩展

新增：

```json
{
  "setup": {
    "target_mode": "full_delivery",
    "complete_for_target": false,
    "next_action": "open_wechat_settings",
    "settings_url": "http://127.0.0.1:3000/settings/wechat"
  }
}
```

`doctor` 只读，不安装依赖、不调用外部服务、不修改 IP 白名单。

### 9.2 Agent 状态机

Skill 主流程精简为：

```text
1. 查找稳定 launcher
2. 不存在 → 读取 INSTALL_FOR_AGENT.md
3. 存在 → doctor
4. 阻断错误 → 按 next_action 恢复
5. 可选能力缺失 → 不阻断排版，只提示本地设置入口
6. 创建任务 → 生成 Brief → 打开人工评审
```

安装细节、微信配置和错误码分别放入 references，避免每次文章任务都加载完整安装说明。

## 10. 数据与迁移

- SQLite 业务 Schema 不因设置中心改变；
- `setup-preferences.json` 位于 `config/`，不进入程序版本目录；
- 微信连接检测结果可以写入 `config/provider-status.json`，只保存时间、状态、错误码和公网 IP 哈希，不保存令牌；
- 旧 `.env.local` 中已有的微信和图片配置自动映射为能力状态；
- 不迁移或回写已经冻结的任务；
- 前端路由变化不改变任务 URL 与任务 ID。

## 11. 安全与威胁控制

| 风险 | 控制 |
|---|---|
| 远程网页修改本地密钥 | 回环地址校验 + `X-Settings-Intent` + 非 CORS 开放写接口 |
| Agent 读取配置文件 | Skill 明确禁止；API 只返回布尔状态 |
| 日志泄漏微信原始响应 | Adapter 先分类再脱敏，只记录稳定错误码 |
| 连接检测误创建草稿 | Probe 接口与 Draft 接口完全分离 |
| IP 查询泄漏访问行为 | 仅用户点击后调用，并允许不使用该能力 |
| 旧版本清理误删数据 | 固定父目录、解析路径校验、current/previous 白名单 |
| 构建产物连接旧 API | 运行时配置 + API/页面版本双校验 |

## 14. 验收门禁

Alpha.15 发布前必须满足：

1. 三种目标模式不会错误阻断基础排版；
2. 换新对话不重复安装、不读取密钥；
3. 微信保存、连接检测、测试草稿是三个独立动作；
4. 工作台和 Agent CLI 可以按需检测同一个公网出口 IP，普通启动和新对话不会自动检测；
5. 生产工作台不运行 `next dev`；
6. 构建产物不会连接旧测试 API；
7. 只保留当前和上一个程序版本，历史数据完整；
8. 三种宿主至少各完成一次安装或升级路径；
9. 运营电脑能打开历史任务并创建一篇真实草稿；
10. 复制正文和下载交付包继续作为不调用微信接口的兜底；
11. 所有自动化测试、Next.js 生产构建和脱敏检查通过。

## 15. 回滚策略

- Alpha.15 安装前停止旧服务，但保留上一版本完整程序；
- 新版本依赖安装或构建失败时不更新 `install.json.current_version`；
- 新版本启动失败时稳定 launcher 可切回 `previous_version`；
- 设置 Schema 采用向后兼容读取，回滚程序仍能读取原 `.env.local`；
- 新增设置文件可被旧版本忽略；
- 回滚不删除 Alpha.15 创建的任务、图片和冻结产物。
