# V1.0 宿主 Agent 原生生图桥接产品与技术决策

- 状态：底层契约保留，可见工作台入口已于 D465–D468 收敛
- 日期：2026-08-25
- 对应决策：D457–D468、D470–D472、D517–D523
- 影响范围：图片工作台、API、CLI、Skill、图片 Provider 文档

## 1. 背景

Visual Director 原有图片能力包括人工上传、Mock、通用 Images API 和 Gemini。对于已经购买 Codex 等宿主订阅、且宿主原生暴露生图工具的用户，再要求配置一套图片 API Key 会增加重复配置和额外费用。

但宿主生图不能直接取代工作台 Provider：文章主题要先由用户确认；生成期间仍可能换主题；不同 Agent 也不一定提供可调用的图片工具。因此本轮增加的是一条可选、显式、异步的宿主桥接链路，而不是新的默认 Provider。

## 2. 已接受产品决策

| 决策 | 内容 | 产品理由 |
|---|---|---|
| D457 | 宿主原生生图只在用户确认当前文章主题后触发 | 避免第一版图片先于主题生成，减少换主题后的风格错配与重复消耗 |
| D458 | 宿主原生生图不是第五种持久图片 Provider | 它依赖当前对话和宿主工具，不能冒充所有安装环境都稳定具备的本地能力 |
| D459 | 用户必须显式要求原 Agent 继续处理图片 | 浏览器不能假设能直接控制宿主；工具调用、额度和责任边界必须可见 |
| D460 | 每条请求绑定任务、方案、图片槽、方案 revision、图片 revision 与 Prompt 哈希 | 保留生成时来源与视觉方向，禁止来源不明的图片静默挂入；主题切换后的处置由 D470–D472 细化 |
| D461 | 宿主图片导入后只成为待审核候选，不自动采用 | 保留现有 OCR、文字核对、大图查看和人工审美门禁 |
| D462 | 宿主没有原生生图工具时透明返回不可用，不静默降级到付费 API | 防止“想省 API 成本”反而在后台产生新的费用 |
| D463 | 原有 API 生图、人工上传、沿用原图、保底图和跳过继续并存 | 宿主桥接是增量入口，不把 Codex 特有能力变成产品硬依赖 |
| D464 | 产品文案只说明“无需额外图片 API Key”，不承诺免费 | 原生生图通常消耗宿主订阅额度；订阅配额与免费 API 是不同概念 |
| D465 | 工作台移除“交给当前 Agent”、复制指令与轮询等待界面 | 该路径慢于直连 API，显性入口与原对话能力重复，增加用户往返成本 |
| D466 | `image context` 与 `image import` 继续作为 Skill 后台契约 | 仍保留主题绑定、版本防错、OCR 与人工审核价值 |
| D467 | 用户在原对话明确要求后，Agent 在后台完成读取、生成与导入 | 用户无需理解 task_id、命令或 Prompt 搬运 |
| D468 | 文档同时说明宿主额度、API 速度与第三方免费额度边界 | 避免把“无需额外项目 Key”误解为免费或更快 |
| D470 | 主题或普通方案 revision 变化不再单独阻断宿主图片导入 | revision 同时承载主题和组件修改，不等于图片语义已经失效；切走再切回也不应浪费已生成图片 |
| D471 | 导入时验证历史请求，并只对正文锚点、图片用途、事实绑定、视觉意图和图片槽 revision 做硬门禁 | 放宽主题切换的同时，继续防止错图挂到已变化的内容位置或已处理图片槽 |
| D472 | 跨主题图片保留生成时 Visual DNA，并按当前主题返回与 API 候选一致的兼容度提示 | 把风格适配交给可解释评分与人工审核，不自动采用，也不强迫用户重新消耗额度 |
| D517 | 已采用或替换的正文图片槽仍可继续下发宿主请求 | 用户先试用工作台 API、再让宿主补充候选是正常路径，不应被状态机阻断 |
| D518 | 删除宿主正文三张候选上限与封面八张候选上限 | 与“持续抽卡、保留历史候选”的产品规则一致 |
| D519 | 宿主导入新正文候选时保留当前采用结果与 decision | 新候选只进入待审核，不造成文章图片闪回或丢失 |
| D520 | `requests=[]` 改为显式 `host_image_handoff_blocked` | 空请求是硬停止，Agent 不得自行补 Prompt 或借普通上传绕过请求绑定 |
| D521 | 宿主封面使用独立 `asset_type=cover` 请求和候选计数绑定 | 复用现有 5:4 封面候选与 2.35:1 显示区，不把封面伪装成正文槽 |
| D522 | 宿主封面导入只新增 `host_generated` 候选，不自动采用 | 保留封面大图审核与显示区调整门禁 |
| D523 | 正文与封面来源分别保存宿主回执 | 工作台可区分工作台图片模型、宿主原生生图和人工上传 |

## 3. 用户流程

```text
Agent 生成文章与 EditorialBrief
→ 本地核心生成推荐主题和图片槽
→ 用户在工作台确认或切换主题
→ 用户在原 Agent 对话中要求“为当前工作台任务生成并插入配图”
→ Agent 读取当前主题绑定的图片请求
→ 宿主原生图片工具生成本地文件
→ CLI 按 request_id 导回对应图片槽
→ 工作台出现待审核候选
→ 用户查看大图并采用、跳过或继续抽卡
```

工作台不会直接连接 Codex、Claude Code 或其他宿主，也不在浏览器中读取宿主账号状态。可见工作台只保留图片 API、人工上传、沿用与跳过；宿主链路由 Agent 在用户明确要求后于后台执行。

## 4. 技术接口

### 4.1 读取受控图片请求

```powershell
& "{launcher}" image context <task-id> --json
```

核心输出 `host_image_generation_context.v0.2`，主要字段：

- `visual_system`：用户当前确认的文章主题；
- `plan_revision`：当前视觉方案 revision；
- `requests[].request_id`：主题与图片槽绑定的确定性请求 ID；
- `requests[].prompt`：已经编译 Visual DNA、内容关系和供应商无关约束的受控 Prompt；
- `requests[].expected_image_revision`：导入时必须匹配的图片槽版本；
- `requests[].locked_copy`：结构信息图允许出现、且来自原文的锁定文字；
- `requests[].asset_type`：`body_image` 或 `cover`；
- `blocked_targets`：没有可执行请求时的目标与阻断原因；
- `output_rules`：宿主不得静默调用付费 API、不得自动采用候选等规则。

正文默认使用上述命令。用户明确要求宿主生成封面时使用：

```powershell
& "{launcher}" image context <task-id> --asset-type cover --json
```

`request_count=0` 时 CLI 返回 `next_action=host_image_handoff_blocked`。这是硬停止状态，Agent 不得自行编写 Prompt、生图或改走普通上传。

### 4.2 导入宿主图片

```powershell
& "{launcher}" image import <task-id> \
  --plan-id <plan-id> \
  --slot-id <image-slot-id> \
  --request-id <request-id> \
  --expected-plan-revision <plan-revision> \
  --expected-image-revision <image-revision> \
  --file "<absolute-image-path>" \
  --host-name "<actual-host>" \
  --host-model "<actual-model-or-host_managed>" \
  --json
```

导入支持 PNG、JPEG 和 WebP，单文件不超过 8 MB。后端继续执行文件解析、比例检查、Visual DNA 快照以及结构信息图 OCR/锁定文字核验；候选持续追加，不设置数量上限。

宿主封面使用独立绑定导入：

```powershell
& "{launcher}" image import <task-id> \
  --asset-type cover \
  --plan-id <plan-id> \
  --request-id <request-id> \
  --expected-plan-revision <plan-revision> \
  --expected-cover-candidate-count <count> \
  --file "<absolute-cover-path>" \
  --host-name "<actual-host>" \
  --host-model "<actual-model-or-host_managed>" \
  --json
```

正文和封面都允许持续追加候选，不设置数量上限。已采用或替换的正文槽不会被重置；宿主新图保持 `pending`，当前采用结果继续生效。

### 4.3 失效保护

| 错误码 | 含义 | Agent 动作 |
|---|---|---|
| `host_image_request_stale` | 请求不存在、已经完成或不再属于当前图片任务 | 刷新工作台，不覆盖当前结果 |
| `host_image_semantic_context_changed` | 正文锚点、图片用途、事实绑定或视觉意图已经变化 | 按当前内容重新读取请求并生成 |
| `host_image_revision_changed` | 图片槽候选或决定发生变化 | 重新读取上下文，不强制导入 |
| `host_image_generation_unavailable` | 当前宿主没有原生生图工具 | 告知用户并保留 API、上传、沿用或跳过入口 |
| `host_cover_request_stale` | 封面请求不存在或已经完成 | 重新读取封面请求 |
| `host_cover_semantic_context_changed` | 文章封面语义已经变化 | 按当前文章重新生成 |
| `host_cover_revision_changed` | 封面候选列表已经变化 | 重新读取请求，不覆盖当前候选 |

主题切换不是错误。核心会从 `expected_plan_revision` 读取历史方案，验证原 `request_id`，保存生成时的 Visual DNA 快照，再针对当前主题计算 `theme_compatibility`。若差异较大，工作台提示“按新主题再生成”，但旧图仍保留为待审核候选。

## 5. 工作台交互

- 不展示宿主 Agent 专属按钮、复制提示或等待回传状态；
- 图片 API、人工上传、沿用原图、保底图和跳过保持原有交互；
- Agent 导入的正文图片与其他候选一致，刷新工作台后进入大图审核；宿主封面显示为“宿主原生生图”；
- 所有宿主候选仍必须由用户人工采用。

## 6. 验收结果

- API：宿主请求生成、文件导入、人工候选状态、跨主题兼容提示以及切走再切回后导入均通过自动化测试；
- CLI：`image context` 与 `image import` 的参数、Multipart 文件回传和 JSON 输出通过测试；
- Web：TypeScript、生产构建通过，可见宿主交接入口已移除；
- 浏览器：配图工作台只保留 Provider、上传、沿用与跳过，控制台无错误；
- 全量后端测试在 Mock 图片 Provider 下通过，保留 1 项原有跳过测试。

## 7. 暂不进入本轮的范围

- 浏览器直接控制宿主 Agent；
- 自动判断当前 Agent 是否有图片工具；
- 在主题确认前预生成宿主图片；
- 宿主生成后自动采用图片；
- 为每一种 Agent 单独维护私有协议；
- 把宿主订阅额度宣传为免费 API。
