# V1.0 手机端模拟预览产品决策

## 目标

在不改变文章 HTML、主题渲染和微信公众号发布链路的前提下，让运营在工作台内快速判断文章在窄屏阅读场景下的节奏与视觉密度。

## 首版范围

- 预览区提供“内容校对 / 手机预览”两种视图。
- 内容校对使用 600px 正文净宽，对齐当前公众号电脑后台的主要排版比例。
- 手机预览固定使用 405px 逻辑视口（正文左右各 24px），对齐产品验收使用的实机截图，不提供多机型切换。
- 手机外壳使用 MIT 许可的 `@sneas/telephone` SVG；项目在其透明屏幕区域内叠加本地实现的公众号阅读页顶部与底部操作栏。
- 两种视图复用同一个工作版本；内容校对修改自动保存并触发确定性重渲染，手机预览随后读取同一版本。
- 内容校对允许像公众号后台一样在原文位置直接修改标题、普通正文、语义组件文案、列表项和表格单元格，不再弹出二级编辑窗口；组件结构、装饰、图片位置和发布资产不可在该入口中破坏。
- 提供沉浸查看模式；按 `Esc` 或点击“退出沉浸”返回工作台。
- 冻结版本的最终预览使用同一套交互，避免编辑阶段与交付阶段体验割裂。
- 界面明确标注“模拟预览”，不承诺与微信客户端像素级一致。

## 非目标

- 不模拟微信客户端全部导航、菜单和真实交互，顶部与底部栏仅用于形成接近手机阅读的视觉环境。
- 不提供多机型、多屏幕尺寸选择。
- 不用手机外壳修改发布后的 HTML；工作台缩放只改变预览显示比例。
- 不把整篇 iframe 设为不受控 `contenteditable`，也不允许删除组件容器、图片槽或装饰节点。
- 不替代真实微信公众号草稿箱与手机预览验收。

## 验收标准

1. 进入工作台后默认显示内容校对视图。
2. 内容校对的正文净宽为 600px，手机预览逻辑视口为 405px。
3. 在内容校对中点击真实文字节点后直接出现光标；停顿后自动保存，编辑过程中不重载 iframe 打断光标，离开文字或切换手机预览后读取服务端确定性重渲染版本。
4. 换主题、切换组件样式或重新打开任务后，已保存文字修改继续存在。
5. 组件结构、装饰节点、图片槽和原始 Markdown 不因文案编辑而被浏览器 DOM 反向覆盖。
6. 桌面窄窗口下控件不溢出，手机文章滚动区不会伸入底部操作栏下方。
7. 冻结 HTML 不包含工作台编辑标记；复制、导出和公众号草稿创建继续使用不可变冻结版本。
8. 修改被结构信息图引用的原文列表时，信息图事实锚点和短标签同步重绑到新文案；已有图片候选仍需人工复核，不因改字自动采用。
9. 用户在文章中段编辑后点击空白区域触发保存与重渲染，内容校对保持原阅读位置；只有显式定位某个组件时才按目标锚点跳转。
10. 十二个主题下，组件正文即使与“证据摘录、来信、回信”等固定标签同处一个节点，也必须只开放原文片段编辑，不把标签和装饰纳入可编辑范围。
11. “证据摘录”等独占一行的正文片段获得焦点时，由正文自身形成规则矩形，不包含上方固定标签；“来信/回信”等必须同行的片段仍保持行内排版，并由所在文字行提供规则高亮。两者都不得按每行文字盒绘制阶梯框或覆盖主题配色。
12. 所有主题的可编辑文字统一采用半透明淡绿悬停/聚焦反馈；编辑表面归一为自身矩形或父文字行两类，页面必须报告完整的编辑块覆盖状态，任何新增主题出现漏映射时均不得通过扩展回归验收。
13. 从内容校对切换到手机预览后，不保留运行时编辑包装、焦点或编辑属性；连续英文、网址及无空格字符必须在 405px 逻辑视口内安全换行，页面 `scrollWidth` 不得超过 `clientWidth`，且不得出现横向滚动条。
