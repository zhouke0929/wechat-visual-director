# V1.0 Agent 调用与 CLI 契约

- 状态：V1.0-alpha.3 已实现契约
- 日期：2026-07-22
- 目标：让 OpenClaw、Claude Code、Codex 和其他可执行命令的 Agent 调用同一套本地视觉主编核心
- 产品原则：运营不手动启动前后端、不手动上传 Markdown、不接触内部任务参数

## 1. 模块边界

```text
Agent adapter
  └─ 生成规范化 Markdown、调用 CLI、向用户反馈状态

Local CLI
  └─ 配置、进程管理、健康检查、任务调用、打开浏览器

Core API
  └─ Preflight、规划、渲染、版本、历史、资产和发布门禁

Web workbench
  └─ 方案、组件、图片、封面、问题与最终人工确认

Publisher adapter
  └─ 微信草稿、Wenyan 或成稿导出（后续路线，Alpha 未实现）
```

Skill 不直接生成 HTML，不持有公众号 AppSecret，不复刻视觉规则。核心 API 不读取 OpenClaw、Claude Code 或其他 Agent 的专属会话文件。

## 2. 命令名称

公开产品与 Skill 名称已确定为 `wechat-visual-director`；本地可执行命令保留简洁的 `visual-director`。

V1.0-alpha.1 最小命令：

```bash
visual-director doctor --json
visual-director serve --detach --json
visual-director stop --json
visual-director task create --file <article.md> --open --json
visual-director task status <task-id> --json
visual-director task open <task-id>
```

V1.0-alpha.3 增加宿主 Agent 规划命令：

```bash
visual-director task create --file <article.md> --no-plan --json
visual-director task context <task-id> --json
visual-director task plan <task-id> --brief <editorial-brief.json> --expected-task-version <version> --host-model <name> --open --json
```

后续命令：

```bash
visual-director config init
visual-director task export <task-id> --format bundle
visual-director task publish <task-id> --target wechat-draft
```

## 3. 通用输出规则

- `--json` 时 stdout 只输出一个 UTF-8 JSON 对象；
- 人类可读日志写入 stderr，避免 Agent 解析失败；
- 成功退出码为 `0`；
- 输入或配置错误为 `2`；
- 本地服务不可用为 `3`；
- 任务被 Preflight 阻断为 `4`；
- 外部 Provider 或发布适配器失败为 `5`；
- 安全停止因进程身份不匹配而拒绝为 `6`；
- 未知内部错误为 `10`；
- JSON 中不得包含 AppSecret、API Key、Cookie 和完整敏感请求头。

统一错误结构：

```json
{
  "ok": false,
  "error": {
    "code": "preflight_blocked",
    "message": "Markdown 预检未通过",
    "retryable": false,
    "details": {
      "findings": ["multiple_h1"]
    }
  }
}
```

## 4. `doctor`

检查：

- 操作系统与架构；
- 本地数据目录是否可写；
- API/Web 版本是否匹配；
- 端口是否可用；
- Agent 适配器是否安装；
- 可选图片 Provider 是否配置；
- 可选微信草稿能力是否配置；
- 配置文件权限和已知凭据泄露风险。

示例输出：

```json
{
  "ok": true,
  "schema_version": "doctor_result.v1",
  "core_ready": true,
  "workbench_ready": true,
  "capabilities": {
    "image_generation": false,
    "mock_image_candidates": true,
    "wechat_draft": false,
    "rich_copy": true,
    "bundle_export": true
  },
  "publishers": {
    "wenyan": {
      "ready": false,
      "installed": false,
      "credentials_configured": false
    }
  },
  "warnings": ["image_generation_mock_only"]
}
```

## 5. `serve`

`serve --detach` 负责以本地模式启动核心 API 与 Web 工作台。要求：

- 已运行且版本兼容时直接复用；
- 未运行时启动并等待健康检查；
- 端口冲突时不得杀死未知进程；
- 数据、PID 和日志写入独立用户目录；
- 默认只监听 `127.0.0.1`，不暴露局域网或公网；
- Agent 退出后服务可以继续运行，用户可显式 `stop`。

## 6. `task create`

### 6.1 输入

```bash
visual-director task create \
  --file C:\path\article.md \
  --article-type tutorial_steps \
  --planner auto \
  --open \
  --json
```

| 参数 | 必需 | 说明 |
|---|---:|---|
| `--file` | 是 | UTF-8 Markdown 文件 |
| `--article-type` | 否 | 显式四类之一；缺失时自动识别 |
| `--planner` | 否 | `auto`、`rule`、`intelligent`；默认 `auto` |
| `--no-plan` | 否 | 只创建任务，不自动生成双方案 |
| `--new-task` | 否 | 即使输入未变化也显式创建新任务 |
| `--plan-timeout` | 否 | 等待方案完成的最长秒数，默认 120 |
| `--open` | 否 | 创建后用系统浏览器打开具体任务页面 |
| `--no-start` | 否 | 不自动启动服务，供测试和受控部署使用 |
| `--json` | Agent 必需 | 返回机器可读结果 |

`task create` 默认先确保服务可用，再复用现有 `POST /api/v1/article-tasks` 创建任务。alpha.1 不重新实现解析、Preflight 和任务存储。

### 6.2 成功输出

```json
{
  "ok": true,
  "schema_version": "task_create_result.v0.2",
  "task_id": "uuid",
  "status": "plans_ready",
  "preflight_status": "REVIEW",
  "planning_allowed": true,
  "draft_creation_allowed": false,
  "idempotency_replayed": false,
  "plans_generated": true,
  "planner": "intelligent",
  "review_url": "http://127.0.0.1:3000/tasks/uuid",
  "opened": true,
  "next_action": "human_review"
}
```

创建任务后，若 Preflight 允许规划，CLI 默认生成双方案并等待 `plans_ready` 后再打开页面；若规划被阻断，则直接打开预检处理界面。CLI 不自动确认 finding、不自动选择视觉方案、不自动创建公众号草稿，因此不会绕过人工确认门禁。

### 6.3 幂等

未显式提供 `--idempotency-key` 时，CLI 根据 Markdown 内容、目标账号和文章类型生成稳定键。同一输入重试会返回原任务；内容变化会创建新任务；确需对同一份原稿另建任务时使用 `--new-task`。API 将键与请求哈希持久化到 SQLite，同键不同请求返回 409，不会静默复用错误任务。

## 7. `task status` 与 `task open`

`task status` 返回任务状态、预检状态和允许动作；不返回完整正文。Agent 根据 `next_action` 反馈用户：

- `fix_source`：原稿存在硬阻断，Agent 可以按 finding 修改后重新创建；
- `human_review`：打开工作台等待人工处理；
- `ready_to_confirm`：方案可确认；
- `mock_draft_created`：只表示本地 Mock 记录已创建，未调用微信接口；
- `failed`：说明可重试动作，不盲目重跑整条链路。

`task open` 只打开现有任务，不创建、不规划、不发布。

## 8. Agent 适配器契约

所有 Agent 适配器执行同一流程：

1. 根据用户需求和资料生成符合 `wechat_article.v1` 的 Markdown；
2. 保存到本次任务的临时文件，不覆盖用户原始资料；
3. 调用 `task create --file ... --no-plan --json` 完成预检；
4. 调用 `task context` 获取解析器生成的块 ID、安全品牌信息、最近视觉摘要和 JSON Schema；
5. 由当前宿主 Agent 生成 EditorialBrief；运行环境原生支持子智能体时可以隔离执行，但不得把子智能体设为必需依赖；
6. 调用 `task plan --brief ... --expected-task-version ... --open --json`；
7. 解析 `planner_provider`、`fallback_used` 与 `normalization_count`，不得把规则兜底描述成 AI 规划；
8. `preflight_blocked` 时只修复明确问题，禁止编造事实；
9. `human_review` 时停止自主操作，等待用户在工作台确认；
10. 用户完成确认后，通过工作台冻结版本，并选择微信草稿、富文本复制或交付包；
11. 未经明确确认不得调用草稿创建，更不得执行最终群发。

不同 Agent 只替换触发描述、文件目录和调用方式，不改变核心业务协议。

## 9. OpenClaw 首发适配器

首版 Skill 计划包含：

```text
skill/
├── SKILL.md
├── scripts/
│   └── visual-director.*
└── references/
    └── article-protocol.md
```

`SKILL.md` 只保留触发条件、主流程、安全门禁和对 CLI 的调用说明；详细 Markdown 协议放入 reference；确定性操作由脚本或核心 CLI 执行。

OpenClaw 只是首发适配器。Claude Code、Codex 等适配器可复用同一 reference 和 CLI，不复制核心代码。

## 10. 安全边界

- CLI 默认仅连接本机 `127.0.0.1`；
- 本地评审 URL 不包含 AppSecret 或模型 Key；
- 密钥不通过命令行参数传递，避免进入进程列表和 shell 历史；
- Agent 只读取能力状态，不读取密钥值；
- 浏览器自动打开失败时仍返回 URL，不把任务判为失败；
- 发布动作与任务创建分离，发布必须绑定已冻结版本和人工确认；
- 安装器不得修改用户已有 Agent 配置而不留备份和回滚记录。

## 12. 验收标准

在已安装开发依赖的 Windows 电脑上，只执行一条 `task create` 命令即可：

- 自动启动缺失的本地服务；
- 创建任务并得到唯一 `task_id`；
- 自动打开 `/tasks/<task-id>`；
- 返回合法 JSON，Agent 无需解析中文日志；
- Preflight 阻断时不打开无效任务；
- 已运行服务不被重复启动；
- 端口冲突、文件不存在和 API 版本不兼容有明确错误；
- 不接触现有视觉规划、渲染和历史逻辑的实现细节。

## 15. Alpha.3 宿主 Agent 规划进度（2026-07-23）

已实现：

- `task context` 返回可安全交给宿主模型的文章块、品牌约束、最近历史、JSON Schema 与输出规则；
- `task plan` 接收独立 `editorial-brief.json`，不要求核心再次调用 Qwen；
- 任务方案元数据记录 `provider=host_agent`、宿主声明模型、规范化次数和规则兜底原因；
- Brief 的未知字段、错误块引用、H1/H2 消费、组件类型冲突和图片事实风险继续由核心校验；
- 无效 Brief 自动降级为规则规划，仍生成双方案，但通过 `fallback_used=true` 明确披露；
- 子智能体仅作为宿主侧可选执行方式，不属于核心依赖。

该模式下 `doctor.capabilities.host_agent_text_planning=true` 只表示核心具备接收能力；是否真实采用宿主规划，以具体任务返回的 `planner_provider=host_agent` 且 `fallback_used=false` 为准。

## 16. Alpha.5 持久安装与无损升级（2026-07-27）

安装器默认使用：

```text
%LOCALAPPDATA%\wechat-visual-director\
├── visual-director.ps1        # 稳定入口
├── install.json               # 当前版本指针，不含密钥
├── versions\<version>\        # 只读程序版本与各自依赖
├── data\                      # SQLite 任务、历史和图片资产
├── config\.env.local          # 用户私有 Provider 与公众号配置
└── runtime\                   # PID 状态与日志
```

约束：

- Agent 必须从安装结果读取 `launcher`，后续不得继续调用临时下载目录；
- 从新 GitHub Tag 重复运行安装器即执行显式升级，新版本写入独立 `versions/` 目录；
- 只有依赖安装成功后才更新 `install.json` 的当前版本指针；
- `data/`、`config/` 和 `runtime/` 不属于任何程序版本，升级不得覆盖；
- 首次持久安装会在目标不存在时迁移源码目录中的旧 SQLite、图片资产和 `.env.local`；
- `doctor.installation` 返回版本、模式、程序目录、数据目录、配置文件和运行目录，但不读取或回显配置内容；
- API `/health` 返回运行版本；`doctor.installation.version_match=false` 或 `core_version_mismatch` 时阻断新任务，避免升级后误用仍占用端口的旧进程；
- 当前不做后台自动更新、自动删除旧版本或隐式卸载。
