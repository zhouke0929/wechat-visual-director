# V1.0 Windows 便携发行包技术设计

## 1. 目标

Alpha.20 将 Windows 普通用户的首次安装从“克隆源码并准备 Python”改为“下载固定 Release 资产并校验后安装”。目标用户只需要 PowerShell、网络和浏览器，不需要预装 Git、Python、Node.js、pnpm 或 Wenyan。

## 2. 产品决策

- Windows 10/11 x64 是首个正式便携包平台；macOS 暂时保持源码安装的技术预览。
- 采用目录型 ZIP，而不是单文件 EXE。这样仍能检查脚本、静态资源、许可证和运行时清单，启动速度也更稳定。
- 包内固定使用 Python 3.11.9 官方 x64 embeddable runtime，并预装后端依赖和生产工作台。
- Release 同时发布 ZIP、`.sha256` 和固定版本 `install-release.ps1`。安装器必须先验证 SHA-256，再执行持久安装。
- 运行数据、图片、凭据和日志继续位于版本目录之外；升级程序不能覆盖它们。
- 便携包不包含匿名盲评语料、内部测试稿、本地数据库、API Key、AppSecret、缓存或构建临时文件。

## 3. 发行结构

```text
wechat-visual-director/
├── runtime/python/                 # CPython 3.11.9 + 固定后端依赖
├── apps/web/dist/                  # Vite 生产工作台
├── assets/ contracts/ references/ # 确定性运行资产
├── scripts/bootstrap.ps1           # 持久安装入口
├── release-manifest.json           # 平台、架构和依赖声明
└── VERSION
```

Release 资产命名固定为：

```text
wechat-visual-director-windows-x64-v<version>.zip
wechat-visual-director-windows-x64-v<version>.zip.sha256
install-release.ps1
```

## 4. 安装与运行

`install-release.ps1` 下载固定标签资产，验证哈希，解压到临时目录，然后调用包内 `bootstrap.ps1`。安装器优先选择 `runtime/python/python.exe`，仅源码开发模式才回退到系统 Python 虚拟环境。稳定入口仍为：

```text
%LOCALAPPDATA%\wechat-visual-director\visual-director.ps1
```

后台服务继承 `VISUAL_DIRECTOR_PROJECT_ROOT`，所以安装到任意本机路径时都从当前版本目录读取品牌、主题、静态工作台与契约。历史盲评数据仅在源码目录存在时启用，不是生产运行依赖。

## 5. 验收门禁

每个 Windows Release 必须通过：

1. Web 类型检查与生产构建；
2. API 全量测试；
3. PowerShell 脚本语法检查；
4. 从 ZIP 解压到全新临时目录；
5. 使用包内 Python 完成 bootstrap、`doctor --json` 和样例任务创建；
6. 验证 `runtime_mode=bundled_python`、`bundled_runtime=true`、运行版本与数据根一致；
7. 安全停止服务并执行 `uninstall -Purge`；
8. GitHub Actions 生成的 ZIP 与 `.sha256` 作为正式 Release 资产。

## 6. 后续演进

后续版本继续由 CI 自动重建并执行相同冒烟测试。只有依赖、Python 运行时或平台脚本变化时才需要调整打包逻辑；普通主题、组件和交互更新只会触发自动重打包，不增加用户安装步骤。
